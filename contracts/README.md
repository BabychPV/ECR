# Контракт

Те, що зв'язує сервер і клієнта. **Поза `docs/`** навмисно: каталог
документації накритий `CHECKSUMS.txt`, і згенеровані файли там ламали б
звірку сум (`D-135`, директива №04 §2.0).

| Файл | Хто пише | Хто читає |
|---|---|---|
| `openapi.snapshot.json` | генератор, за явним `ECR_UPDATE_SNAPSHOT=1` | тест `OpenApiSnapshotTests`, `npm run api:types` |

## Навіщо знімок

`A7-34`, `A7-35`, `A7-36` і `A7-38` — не чотири помилки, а чотири прояви
одного: **клієнт мав власні рукописні типи відповідей, і ніщо не звіряло їх
із тим, що сервер справді віддає.** Розбіжності не видно в жодному з двох
файлів окремо — лише між ними, а між ними не дивився ніхто.

Тепер ланцюг замкнений:

```
код сервера → /openapi/v1.json → openapi.snapshot.json → schema.d.ts → екрани
```

- зміна коду відповіді розходиться зі знімком → тест червоний, із номером рядка;
- знімок розходиться з `schema.d.ts` → `verify-all` падає;
- екран описує форму сам → лінт падає (`D-137`).

## Оновлення знімка

```
ECR_UPDATE_SNAPSHOT=1 dotnet test tests/Ecr.Api.Tests --filter FullyQualifiedName~OpenApiSnapshotTests
npm --prefix src/Ecr.Web run api:types
```

Тест **падає навіть після успішного перезапису** — навмисно, щоб оновлення не
пройшло повз рев'ю разом із зеленою збіркою. Це зміна контракту: діф має
прочитати людина.
