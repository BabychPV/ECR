# E4. Приймання звіту агента

Звіт — це заява; приймаємо за артефактами, від дешевого до дорогого, щоб повернути якомога раніше.

1. **Табло:** `python gates\board.py --repo H:\ECR` — у картки немає «AC без SHA», SHA знаходяться.
2. **Коміти і межі:** `git -C <папка> log --oneline origin/main..HEAD` і `git -C <папка> diff --stat origin/main...HEAD` — збігаються зі звітом; змінені файли — у межах «Можна змінювати».
3. **Чесність тестів** (той самий сторож, що в Evidence; Git Bash, у робочій папці агента):
   `BASE_SHA=$(git merge-base origin/main HEAD) HEAD_SHA=HEAD bash .github/guards/honesty-guard.sh`
   Бачить лише закомічене; незакомічене покаже `wt_audit.py`.
4. **AC по одному:** для кожного — код і тест у diff. Немає тесту — AC не виконано. Тестові файли, змінені поза планом, — перевір, чи тест не підігнано під код.
5. **Вплив:** кожен пункт розділу 3 має відповідь; одне-два «ні, бо …» перевір сам пошуком.
6. **Тести часу:** не повторюй 20× сам (23.11 у 90 хв вклалось 4/20) — перевір trx: кількість, SHA, дату; `route.py --kind timing` тоді казав ЛОКАЛЬНО.
7. **R3 — незалежний огляд:** агент (opus), який код не писав. Вхід — картка, DESIGN і diff, БЕЗ звіту автора. Перевіряє: кожен AC доведено тестом, що впав би на зламаному коді; формат тестових даних = продакшн; пункти впливу. Те, чого машина не бачить (асерт, підігнаний під фактичний результат), бачить лише він.
8. **Чистота:** `python gates\wt_audit.py --repo H:\ECR` — основна папка без позначок.
9. **Вердикт** у розділ 5: `accepted` або `returned` з дельтами («AC-2: немає тесту на …»). Часткового приймання немає: знахідка — новий AC цієї ж картки. Статус оновити.
