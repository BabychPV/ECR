Людина (моє вікно «Аудит», 03.10, після мержу #476): «Правило — мерж сам, якщо це не завадить іншим сесіям».

**Why:** кожен RC я вже перевіряв (7 гейтів, оновлення main→RC ×2, smoke, e2e, живі перевірки), а питання «Так, мержити» лише гальмувало швидку розробку.

**How to apply:**
- RC-PR `rc/*` → `main` мерж сам: `gh pr merge N --merge` БЕЗ `--delete-branch`, без squash; лише після власної перевірки `gh pr view N` (усі записи statusCheckRollup SUCCESS крім skipped, head = перевірений sha, MERGEABLE) і всіх передмержових перевірок (upgrade main→RC ×2, smoke, e2e, живі).
- «Не заважає іншим сесіям»: перед мержем переконатись, що координатор/«Аналіз» не проводять на main/стенді тест, який залежить від незмінного main, і немає відкритого блокера (P0/P1, відкрите питання людині, що стосується складу RC); якщо є — НЕ мержити, написати координатору й чекати; після мержу одразу повідомити координатора (хеш main).
- Лишається незмінним: ніколи `--admin`, мерж по червоному/in_progress, `--force`, `--no-verify`; для рішень, що змінюють продукт без підтвердження людини (D-записи «рішення людини») — питати; дія не обходить класифікатор.
- Пов'язано: [[orchestrator-only]], [[merge-cadence]].
