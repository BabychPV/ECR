**2026-09-20, пряма вказівка користувача — процес змінено:** «перестань
робити багато пулреквестів, зроби тільки один і докидуйте разом з іншою
сесією туди зміни… закривати пул реквест один раз на тиждень».

- Спільна гілка **`dev/integration`**, один PR у `main` (перший — #453).
  Обидві сесії (бекенд і клієнт) комітять туди.
- Окремих PR на підзадачу більше НЕ відкриваємо.
- Мерж у `main` — **раз на тиждень**, і тільки по семи зелених гейтах.
- Червоний гейт лагодиться наступним комітом у ту саму гілку, не окремим PR.
- Порядок пушу: власна гілка від `origin/dev/integration` в окремому
  worktree → `git fetch` → `git rebase origin/dev/integration` (ребейз лише
  НЕзапушених комітів, `--force` лишається забороненим) →
  `git push origin HEAD:dev/integration`.
- Спільні файли (`09-seed.sql`, `openapi.snapshot.json`, `schema.d.ts`,
  `shared/ui/**`) — попереджати іншу сесію повідомленням; перегенерацію
  контракту робити ОСТАННІМ кроком після rebase.

⚠ Ризик, який треба тримати в голові: тиждень роботи живе поза `main`, і
зелений гейт тут означає «зелена гілка», а не «зелений `main`». Пом'якшення —
щоденний rebase і `git merge origin/main`, щойно в `main` щось доїжджає.
