30.10 людина: «Потрібно щоб ти сам визначав коли доцільно запускати саб агентів, мета якість нашого продукту та економія токенів». Правило для координатора й усіх сесій (Аналіз, Permites, Аудит-2). Уточнює [[orchestrator-only]]: «усе через сабагентів» більше не догма.

**Запускати сабагента, коли:**
- незалежні частини в НЕперетинних файлах можна робити паралельно (виграш часу);
- широкий пошук/читання багатьох файлів, а потрібен лише висновок (основний контекст лишається малим);
- незалежна/змагальна перевірка ризикового (міграції, безпека, дані, контракт) — якість;
- довгий важкий прогін (стенд, F13, e2e), щоб не тримати основний контекст.

**Робити самому, без сабагента:**
- відомий файл/символ, разовий пошук, команда, правка <~50 рядків в одному файлі;
- задача спирається на багато контексту розмови (краще самому або fork);
- уже делегований пошук — не дублювати, чекати результату.

**Економія токенів:** короткий бриф (файли, DoD, заборони); просити короткий звіт (вердикт + file:line, без вивантаження файлів); для read-only пошуку — дешевша модель; продовжувати наявного агента через SendMessage замість нового; агент не лишає фонових циклів.
**Якість:** заяви сабагента перевіряти самому (git diff/log, gh CI) перед звітом; бюджет навантаження машини ([[machine-load-budget]]) і CPU-пауза під вікна стенда діють.
