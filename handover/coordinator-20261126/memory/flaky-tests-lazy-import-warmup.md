2026-09-21 розібрано ~10 плаваючих тестів клієнта. Корені були такі:
- **Лінивий `import()` сторінки чи модалки.** Холодне завантаження під навантаженням займає до 1.6 с, а `findBy*`/`waitFor` чекають 1 с. Рецепт — прогрів модуля в `beforeAll`; компонент далі монтується через `lazy()`. Коміти `dd65f81b` (палітра), `bad2569b` (DataSourceCrud, PeriodsPage, SecurityPage, AsyncBoundary тощо).
- **Пачки 5-секундних таймаутів у різних файлах одночасно.** Прогін тоді триває 150–250 с замість 55–95. Причина — перевантаження машини процесами поза набором: e2e-стенди, Playwright, dotnet інших сесій. Зменшення `maxWorkers` не допомагає: набір лише повільніший, падінь стільки ж.
- **Навантаження для відтворення.** `Start-Job` × N в PowerShell крутить лише частину процесів. Краще один процес Node з N потоками.

**Why:** «підняти таймаут» ховає проблему, а падіння під чужим навантаженням виглядають як вади тестів.

**How to apply:**
- таймаут першого тесту файлу з лінивим компонентом → прогрів у `beforeAll`;
- повний `npm test` не запускати одночасно зі smoke/e2e;
- пачку різних таймаутів спершу перевіряти на завантаження машини.
