Для кожної клієнтської зміни, що чіпає поведінку (фокус, кроки майстра, діалоги, календар, скрол-області), перед пушем: (1) `npx vitest run --config vitest.a11y.config.ts <торкнуті файли>` — звичайний vitest його не включає; (2) ОДИН локальний e2e на стенді (`tools/e2e-stand.ps1 -Grep …`) з тим самим сценарієм у реальному браузері, повторений кілька разів (N/5), а не «до першого зеленого».

**Why:** 20–21.10 Permits: p2-ui прибрала передвибір типу в майстрі → a11y (light) у CI червоний (зелений звичайний vitest); «флейк» фокуса на «More» у першому локальному e2e виявився гонкою меню/діалогу, що впала в CI y31; PA3-U-02 фікс спершу був лише jsdom (скрол-регіон) — потрібен був axe у браузері. jsdom не рахує контраст/layout.

**How to apply:** у промпті клієнтським агентам прямо писати a11y-конфіг + локальний e2e + «трасування першим при падінні»; «один повтор зелений» не є доказом гонки. Спільні `shared/ui`, `shared/dates` — ризикові: повний CI, попередження сесіям. Див. [[verify-ci-not-local-subagent-claims]] і [[full-suite-before-push]].
