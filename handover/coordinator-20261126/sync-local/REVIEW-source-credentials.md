## 2. Відповіді на конкретні питання завдання

- Витоки: GET/list/DataSourceView — безпечно за побудовою (ToView явні поля, DataSourceHandlers.cs:95-106). Реальні ризики: R-02 (логування винятку драйвера цілком), R-12 (record ToString), R-14 (аудит), R-15 (тест по всіх виходах). Телеметрії DB та sensitive-логування EF у коді немає. Експорту/резервної копії конфігурації джерел у src не знайдено (grep по Export/Backup для DataSource порожній).
- Інʼєкція через `;` в UserName: builder екранує, але потрібні валідація й тест (R-13).
- RequireNoCredentials: не обходиться новим режимом (вона на endpoint/secondary, DataSourceHandlers.cs:502-503), але СЬОГОДНІ не ловить uid/user id (R-04) і не ловить пароль, відокремлений табуляцією/переносом.
- Міграція: наявні рядки = Windows за DDL-default, відкат див. R-16/R-17.
- Права й викрадення пароля через зміну цілі: захист задуманий (S1), але без тесту (R-09) і з розбіжністю парсерів (R-10).
- Тест на незбереженій формі: R-01.
- DataProtection: збій розшифровки й блокування облікового запису: R-03.
