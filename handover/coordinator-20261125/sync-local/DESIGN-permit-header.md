# DESIGN: «обов'язковий Permit» у шапці документа (ФВ-5.20)

Дата: 2026-10-07. Статус: проєкт для хмарної лінії, НЕ рішення. Джерела: `docs/tz/02-requirements.md`
(ФВ-5.18…5.20a, ФВ-8.1/8.4/8.5, ФВ-9.15a), `docs/tz/10-decisions.md` (D-146), `docs/reference/design/06-tz-architecture.md`
§5.3 (рядок 941), код `src/Ecr.Application/Security/PeriodAccessRules.cs`, `Ecr.Domain/Entities/Configuration/{HeaderFieldDef,PeriodAccessRuleDef}.cs`,
`Ecr.Application/Documents/{DocumentHeaderHandlers,ValidateDocumentHandler}.cs`, `Ecr.Application/Workflow/SubmitSheetHandler.cs`,
`Ecr.Application/Validation/*`.

## 0. Застереження щодо вхідного завдання

- «D-11 Permit не примушується» у `docs/` НЕ знайдено: `D-11` = «Мови EN+RU+KZ» (і посилання на секрети). Рішення про те, що
  Permit не примушується, письмово не зафіксоване; найближче — текст ФВ-5.20 (нижче). Номер рішення — **факт невідомий**.
- Слова «обов'язковий Permit у шапці» в `docs/tz` **немає**. Слово «шапка» в `docs/tz/02-requirements.md` взагалі не вживається
  (там лише `HDR.` як префікс виразів, ФВ-9.15a). Тому нижче розділено: що каже ТЗ, що є в коді, що є лише пропозицією.

## 1. Що каже ТЗ

1. **ФВ-5.20 «Permit-правила»** (перенос VBA `ApplyPermitMonthLocks`): дозвіл із вікном дії блокує місяці поза вікном.
   Механізм — правило доступу виду `SourceWindow` (ФВ-2.15): називає **колонку рядка**, у якій рядок обирає дозвіл; бере
   `ValidFrom/ValidTo` обраного запису довідника; звіряє з місяцем колонки (`ColumnDef.MonthNumber`), як **відрізок**.
   Відмова — `EditDenyReason.OutsidePermitWindow`, поведінка за `onOutOfWindow` (ФВ-2.16).
2. Там же прямо: «Рядок без обраного дозволу правило **не блокує** — інакше обрати дозвіл було б неможливо». Це і є
   «Permit не примушується» на рівні правила доступу.
3. ФВ-8.1: `Permit` — звичайний запис універсального довідника (з каскадами і M:N; ФВ-8.4: `WaterBody` фільтрується обраним
   `Permit`). ФВ-8.5: вікно дії — властивість запису довідника, але вплив на доступність місяців — це правило доступу, не довідник.
4. `docs/reference/design/06-tz-architecture.md` §5.3 (довідковий, НЕ нормативний `docs/tz`): валідація рівня **Документ при
   `Submit`** — «permit обрано і дійсний, рік у межах проєкту, усі обов'язкові аркуші заповнені». Єдине місце, де «Permit
   обов'язковий» згадано, і воно описує *валідацію*, не правило доступу.
5. Мовчить: чи Permit є полем **шапки** (документ-рівень) чи колонкою рядка; чи один Permit на документ; як вікно Permit
   діє на документ з кількома Permit; що робити, коли Permit змінено після введення даних.

Висновок: за ТЗ ФВ-5.20 — це правило **рядка** (SourceWindow, колонка-джерело), «обов'язковість» у ньому свідомо відсутня.
Обов'язковий Permit у **шапці** — це або нова вимога, або читання 06-tz-architecture §5.3 (валідація Submit).

## 2. Що вже є в коді

| Механізм | Стан |
|---|---|
| `PeriodAccessRuleKind.SourceWindow` (`PeriodAccessRules.SourceWindow`) | Є. Джерело — **колонка** (`SourceColumnDefId`), не поле шапки. Рядок без значення → `Allowed`. Немісячна колонка → `Allowed`. Напівінтервал `[ValidFrom, ValidTo)`, місяць-відрізок. Заборона виграє (жорстка), `Warn`/`AllowWithConfirmation` не блокують. |
| Факти для правила | `PeriodRuleFacts.SourceValues` (код колонки → `SourceValidity`), збираються `AccessDecisionService` (~1364-1391) наперед. Шапка у фактах **відсутня**. |
| `HeaderFieldDef` (шапка) | Є: `Code`, `Label`, `DataType` (String/Int/Decimal/Bool/Date/Lookup/Unit; без Formula/Calculated), `IsRequired`, `LookupRegistryDefId`. `ValidateValue` → `ECR-HDR-0422` (тип/обов'язковість). Клон версії шаблону копіює `HeaderFields` (`TemplateVersionCloner`:149). |
| Обов'язковість шапки | Перевіряється **лише при `PATCH` шапки** (`DocumentHeaderHandlers`): порожнє обов'язкове поле → `ECR-HDR-0422` (`err.ECR-HDR-0422.validationBlocked`). Поле, якого ніколи не торкались, запису не має → **при `Submit` порожня обов'язкова шапка не блокує**: у `SubmitSheetHandler`/`ValidateDocumentHandler` є перевірка `ColumnDef.IsRequired` для колонок (рядок ~440-458), для `HeaderFieldDef.IsRequired` — не знайдено (пошук `IsRequired` у Workflow дає лише колонки). Підтвердити тестом перед роботою. |
| `HDR.<Код>` у виразах | Є: `Parser`, `ReferenceResolver` (рядок ~107), `IEvaluationContext.GetHeader`, `ValidationEvaluationContext.Headers` (передаються в Cell/Scope-валідацію з `IDocumentHeaderStore.GetExpressionValuesAsync`). Тобто правило валідації `Error` на шапку можна написати вже сьогодні: напр. `HDR.Permit <> NULL` (синтаксис порівняння з порожнім — **перевірити**; вирази діалекту шаблонів — окремо від діалекту методологій, «HDR.» формально лежить в Methodology; для Validation-контексту `GetHeader` є). |
| Правила валідації Document-рівня | ТЗ ФВ-5.18: `Scope` Cell/Row/Table/Document. У коді `ValidationRule.Scope` — `byte`; `TableValidation` викликає `ValidateScope(scope: 1…)` для рядка/таблиці. Чи обчислюється Document-рівень (4) і де — **не з'ясовано**, перевірити. |
| `PeriodAccessRuleDef` при клонуванні версії | У `TemplateVersionCloner` рядків про `PeriodAccessRules` **не знайдено** (клонуються формули, правила валідації, шапка). Якщо правила доступу не переходять у нову версію — це окремий потенційний дефект (не підтверджено; перевірити, перш ніж проєктувати «клон PeriodAccessRule»). |
| Помилки/ключі | `ECR-HDR-0404` (поле не знайдено), `ECR-HDR-0422` (+ ключі `err.ECR-HDR-0422.*`), `EditDenyReason.OutsidePermitWindow`, `ECR-TMPL-0422` для конфігурації. Окремого коду «Permit не обраний» **немає**. |

Чого за ТЗ немає у сервері (прогалини):
1. Примусу «Permit обрано» як умови редагування/подання — ТЗ його навмисно не вимагає (п. 1.2); в 06-tz-architecture вимагає лише на `Submit`.
2. Серверної перевірки «Permit дійсний» (вікно дії охоплює період документа) на рівні документа — є лише побічно через блокування місяців рядка.
3. Джерела вікна з **шапки**: `SourceWindow` читає лише колонки рядка.
4. Правил проєкту, що змушують шаблон мати Permit-поле (публікація шаблону без Permit-колонки/поля не попереджає).

## 3. Пропонований контракт для хмарної лінії

Принцип: нічого не вигадуємо в ТЗ; пропонуємо мінімальні розширення, кожне — за явним рішенням координатора/людини.

### Варіант A — «правило шаблону»: Permit обов'язковий через валідацію (без нового коду домену)
- Адмін шаблону додає поле шапки `Permit` (тип `Lookup`, `LookupRegistryDefId` = довідник Permit, `IsRequired = true`).
- Правило валідації рівня Document/Table (`Severity = Error`) з виразом, що читає `HDR.Permit` і `REGFIELD(...)`
  (напр. дійсність вікна — `REGFIELD(HDR.Permit,'ValidTo')`; наявність таких функцій над шапкою — **перевірити**, DIRECTIVE-16
  WR-03 вже робить `REGFIELD([Permit],'Limit')` для колонки).
- Серверна частина: (1) `SubmitSheetHandler`/`ValidateDocumentHandler` перевіряють `HeaderFieldDef.IsRequired` для **ненаявних**
  значень (зараз пропускають — п. 2) → `ECR-HDR-0422`, ключ новий `err.ECR-HDR-0422.requiredAtSubmit` (рядок сіду EN/RU/KZ);
  (2) тест «порожня обов'язкова шапка блокує Submit» + мутація (прибрати перевірку → червоний).
- Контракт: без нових ендпоінтів; змінюється лише поведінка `Submit`/`validate` (відповідь `ValidationMessage` з кодом шапки,
  `scope = Document`). `openapi` не змінюється (якщо не додається поле `headerFieldCode` у `ValidationMessage` — тоді snapshot+schema.d.ts).
- Плюси: узгоджено з ТЗ (правило шаблону, керується метаданими), не чіпає D-146. Мінуси: «дійсний» залежить від виразу в шаблоні.

### Варіант B — «вбудоване»: SourceWindow із шапки + обов'язковий Permit у PeriodAccessRule
- `PeriodAccessRuleDef` + поле `SourceHeaderFieldDefId` (nullable; XOR із `SourceColumnDefId`; `CK_PAR_Kind` оновити); міграція
  (токен міграцій), клон у `TemplateVersionCloner` (+ ремап `HeaderFieldDef.Id` — як для колонок), `PeriodRuleFacts` отримує
  `HeaderSource` (вікно обраного Permit шапки), `PeriodAccessRules.SourceWindow` читає або колонку, або шапку.
- Обов'язковість: нове значення `OnMissingSource` (Allow — за замовчуванням, зберігає ФВ-5.20; Deny — «без Permit не можна»)
  → причина `EditDenyReason.PermitRequired` (новий; `ErrorCodes`+`ExceptionHandlingMiddleware`+`02-contracts.md §7`+ключі 3 мови).
  ⚠ Deny на шапку, що ще порожня, не має блокувати сам `PATCH` шапки (інакше Permit обрати неможливо — той самий парадокс, що в ТЗ).
- Контракт: DTO правила (`PeriodAccessRuleHandlers`: `SourceHeaderFieldDefId`, `OnMissingSource`) → `openapi.snapshot.json`,
  `schema.d.ts`, клієнт редактора правил, матриця доступу (`GetAccessMatrixHandler`).
- Плюси: Permit як шапка документа природно діє на всі аркуші. Мінуси: зміна доменної моделі й ТЗ (ФВ-2.15/5.20 говорять «колонка»),
  міграція, зона `docs/tz/**` (D-нн, сума CHECKSUMS), ризик парадоксу вибору Permit.

### Рекомендація
**A як перший крок** (малий: ~1 серверний фікс + тест + ключ сіду + конфігурація шаблону; без міграції і контракту), бо:
порожня обов'язкова шапка при Submit — реальна прогалина незалежно від Permit. **B** — лише якщо замовник підтвердить, що Permit
має жити в шапці документа й керувати доступом (факт замовника невідомий). Дефолт до відповіді: **A**.

### Оцінка обсягу
- A: S (≈ 150-250 рядків diff, ≥ 40 % тестів; 1 lane, без міграції/контракту; ризик — вирази над шапкою в Document-валідації).
- B: L (міграція + модель + клонування + Evaluate + DTO/контракт + клієнт редактора + матриця доступу + ТЗ-рішення + ≥ 3 нові
  ключі ×3 мови; розбити на 3-4 порції; токен міграцій; зміна `docs/tz` — тільки через «Аудит»).

## 4. Відкриті питання

1. **Факт замовника невідомий:** Permit — це поле шапки документа чи колонка рядка? (ТЗ і VBA-перенос: колонка рядка.) Дефолт: колонка (як є).
2. **Факт замовника невідомий:** обов'язковий Permit — блокує *редагування*, *Submit* чи лише попереджає? Дефолт: блокує Submit (06-tz-architecture §5.3), редагування не блокує (ФВ-5.20).
3. Один Permit на документ чи кілька (по рядках)? Дефолт: за поточним — по рядках.
4. Що робить зміна Permit у шапці після введення даних (перерахунок блокувань, позначка `IsLateEdit`)? Мовчить; дефолт — тільки перевірка при наступній дії.
5. Перевірити в коді: (а) чи блокує `Submit` порожня `HeaderFieldDef.IsRequired` (за читанням — ні); (б) чи копіюються `PeriodAccessRules` у нову версію шаблону; (в) чи виконується валідація Scope=Document; (г) синтаксис порівняння `HDR.X` з порожнім.
6. Номер/текст рішення «Permit не примушується» — у `docs/` не знайдено; якщо воно існує (сесія/лист) — додати посилання, інакше завести `D-нн` у `docs/tz/10-decisions.md` через «Аудит».
