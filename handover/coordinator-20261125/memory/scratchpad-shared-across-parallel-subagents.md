2026-09-22: сабагент (`refactor/rulecoverage-querykeys`) писав повідомлення коміту
у файл під `C:\Users\Babyc\AppData\Local\Temp\claude\H--ECR\<sessionId>\scratchpad\`
і викликав `git commit -F <шлях>`. У коміт потрапив ТЕКСТ ІНШОЇ задачі
(рефакторинг `StatStrip`/`Hint`, який робив зовсім інший паралельний
сабагент) — файл на диску змінився між `Write` і моментом, коли `git
commit -F` його прочитав. Diff коміту лишився правильний (торкнулись лише
свої 2 файли), постраждав тільки текст повідомлення.

**Why:** скретчпед-каталог — один на СЕСІЮ, не на сабагента. Кілька
паралельних сабагентів (кожен у своєму `git worktree`) пишуть у ТОЙ САМИЙ
`scratchpad/`, і навіть унікальні на вигляд імена файлів (`msg-<задача>.txt`)
не рятують, якщо два агенти випадково вибрали однакову назву чи один
переписав файл іншого в проміжку між `Write` і читанням.

**How to apply:** коли доручаю сабагенту писати повідомлення коміту у файл
для `git commit -F` — вимагати писати його ПРЯМО В РОБОЧЕ ДЕРЕВО worktree
(напр. `<worktree>/.git/COMMIT_MSG_TMP` чи будь-який шлях усередині самого
worktree, не в спільному scratchpad) і звіряти вміст `Read`-ом ОДРАЗУ перед
викликом `git commit -F`. Уже застосовую в промптах вимогу «унікальні назви
файлів у scratchpad» — цього недостатньо, бо колізія не в назві, а в
самому факті спільного каталогу між паралельними процесами.
