410: мутація зараховується лише тоді, коли збірка ПРОЙШЛА і очікуваний тест ЧЕРВОНИЙ. Мутація, що не компілюється, нічого не доводить. У кожній таблиці мутацій — колонка «build OK». Мутації писати так, щоб аналізатори мовчали: `false && cond`, `cond && x.Id < 0`, ранній вихід зі збереженим використанням змінної — а НЕ видаленням використання параметра (CS9113 «unread parameter») чи `if (false)` (CS0162 «unreachable code»), бо `TreatWarningsAsErrors`.

411: новий e2e-крок, що залежить від даних стенда, — спершу локально `tools\e2e-stand.ps1 -Grep <spec>`, потім пуш (економить 30–50 хв червоного CI).

**Why:** 16.11 сім мутацій довелося переробляти (у т.ч. мої три в B141: CS9113 / CS0162), а скрипт показував їх як «BUILD ERROR», що легко сплутати з червоним.

**How to apply:** у скриптах мутацій розрізняти build error (регулярка `': error [A-Z]+\d+'`, з урахуванням регістру) і червоний тест; build error = мутацію переписати й прогнати знову. Пов'язане: [[rule-401-mutate-every-branch-before-ready-1116]].
