# Цикл розробки ECR: ворота від вимоги до live (v4)

Доповнює правила координатора і CLAUDE.md, нічого в них не скасовує.

**Принципи**
- Помилку ловимо на найдешевшому етапі, де її можна спіймати. Повний CI, репетиція і live підтверджують, а не шукають.
- Де можна — команда, а не правило. 23.11 правило «"працює" без "на live" не кажу» вже існувало, а NAE (16:20) і B74 (19:25) — та сама помилка двічі; листи готовності перестали писати після 19.11.
- Стан підзадачі живе в картці й git, не в контексті сесії: `board.py` відновлює його після /compact і перезапуску.
- Механіку викликає cron, а не пам'ять: щогодини `hourly.py` (ref\07). 23–24.11 скрипти запустили лише раз при встановленні — і за добу картки застаріли, LIVE-SHA лишився на W15y, диск H: дійшов до 0 ГБ.
- Без боргів: знахідка — новий AC тієї ж картки.

**Скрипти:** `H:\ECR\.sync-local\gates\` (далі `gates\`), Python 3, лише стандартна бібліотека, нічого не змінюють. Перший запуск і після оновлення git або Python: `python gates\test_gates.py`. Git не в PATH → змінна `GIT` або `--git <шлях>` (той, що в ctl.ps1).
**Довідники етапів:** `gates\ref\` — читай файл етапу, коли до нього доходиш.

| E3 Бриф і агент | ≥ 6 ГБ пам'яті і ≥ 20 ГБ диска; бриф = картка + контракт; статус briefed → in-progress | `route.py --kind agent --disk H:\` | ref\03 |

**Статуси картки** (рядок «Статус:»): planned → briefed → in-progress (returned) → reported → accepted → batched <пачка> → rc → main → live-verified → closed. Оновлювати на кожному переході; `board.py` звіряє кожен статус із git.

## Завжди
- Щогодини — `hourly.py` з cron (ref\07). Кожну [!] розібрати в тому ж контролі; «OK» — нічого не робити.
- Перед словами «готово», «на стенді», «працює»: `python gates\where_is.py --repo H:\ECR <SHA кожного AC>`. Людині — саме його відповідь. AC без SHA = не зроблено.
- Перед важким прогоном (повні набори, smoke, тести часу) і перед новим агентом — `route.py`: CI, локально чи чекати, з вимірами (рішення людини 23.11: «залежить від навантаження гітхаба або локального пк»).
- Нічого не видаляти; бази ECR, EcrLandUi, FLERT, EcrLegacyProd — не чіпати; дані live — лише зі слова людини.

## Чого скрипти не бачать — і що замість них
- Неправильно зрозуміла вимога → AC-0 з даними людини + квіз (ref\01).
- Тест, підігнаний під фактичний результат (honesty-guard прямо каже, що машині це невидиме) → незалежний огляд R3 на дизайні й прийманні (ref\01, ref\04).
- Якість дизайну, продуктивність, права → розділ «Вплив» картки й DESIGN (ref\01).
- Те, що проскочило все це → пропуск на ретроспективі й нова перевірка (ref\07). Скіл не обіцяє нуля прогалин; він робить кожну видимою і закриває її перевіркою.
