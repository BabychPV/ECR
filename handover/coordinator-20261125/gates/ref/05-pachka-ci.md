# E5–E6. Пачка і CI

## E5. Зведення пачки `lane/integ-bN`
1. `python gates\board.py --repo H:\ECR` — усі картки пачки `accepted`, без [!].
2. `python gates\overlap.py --repo H:\ECR <гілки пачки>` — перетини файлів і гарячі файли. Для кожного перетину — тест або сценарій взаємодії, запис у TRACKING.
3. Гарячі файли при зведенні:
   - міграції — один ланцюжок у погодженому порядку (як b11: D568 → NAE → MS → builder → L7); знімок EF перегенерувати;
   - SeedReviewed перезакріпити;
   - `docs/tz/10-decisions.md` і `docs/CHECKSUMS.txt` — лишати обидва рядки, суми перерахувати;
   - контракт — перегенерувати останнім кроком.
4. Зводити в окремій робочій папці; build + Ecr.Architecture.Tests.
5. Повні набори чи smoke перед пушем — лише за `python gates\route.py --kind full|smoke --disk H:\` (CI / ЛОКАЛЬНО). Двох важких одночасно не запускати.
6. Картки → `batched lane/integ-bN`, рядок «Пачка:»; `board.py` перевірить, що SHA кожного AC справді в пачці.
7. Один пуш → повний CI.

## E6. CI
- Контур гілок агентів — за ризиком (ref\02).
- Червоний тест: знайди гілку-власницю (чий цільовий набір, чий код покриває). Класифікуй:
  - дефект гілки або взаємодія гілок (перетин, пропущений у кроці 2) → виправлення в гілці-власниці; тест падає до виправлення;
  - нестабільний — лише з доказом: падає і на origin/main (20 повторів). Записати в `.sync-local\flakes\`. Без доказу — дефект;
  - інфраструктура (як `pwsh exit 139 SIGSEGV`) → один `rerun --failed`; вдруге за день — окрема картка на CI.
- Повний CI заново — один раз, коли виправлено все впале, а не після кожного виправлення.
- Кожен червоний CI пачки — питання «на якому дешевшому кроці могли спіймати?» (ref\07).
