# Технічне завдання: ECR Web

**Версія:** 1.2 · **Дата:** 2026-09-04

Універсальний інструмент структурованої звітності. Перша область застосування —
екологічна звітність (ECR), яка сьогодні працює на Excel/VBA (24 аркуші,
~45 000 рядків VBA) і бекенді на SQL / CLR / PI AF / SSRS.

## Що це замінює

Це ТЗ консолідує 40 робочих документів у зв'язний текст із явними рішеннями.
Робочі редакції лишаються доступними в [`../reference/`](../README.md#reference)
як обґрунтування — вони детальніші, але можуть містити вже переглянуті
формулювання. **При розбіжності правий цей текст.**

| Джерело | Що взято |
|---|---|
| `reference/as-is/` (5) | аналіз чинного Excel-контуру |
| `reference/design/` (13) | проєктування, стек, безпека, продуктивність |
| `reference/backend/` (23) | пакет backend-архітектора: фізична модель, вирази, шлях запису, runtime |

## Що змінилося у версії 1.2

| Зміна | Наслідок |
|---|---|
| Архівація без `SWITCH PARTITION` (D-23) | виправлено неможливу операцію у вихідному ТЗ |
| Партиційний ключ `PeriodKey` (D-22) | вирівняні індекси, −0.9 ГБ/рік |
| Standard як базовий режим SQL (D-28) | Enterprise вмикається автоматично, на числа не впливає |
| Нічого не затирається (D-25) | обсяг керується рівнями зберігання |
| Запису в AF немає взагалі (D-44) | споживачі AF переводяться на SSRS/API — пункт runbook |
| SSRS лишається (D-52) | веб-переглядач звітів виходить з обсягу |
| Water/Waste — перший розділ нової системи (D-56) | вертикальний зріз = перший реліз |
| Реєстр одиниць `uom` (D-73…D-79) | конверсії перевіряються при публікації |
| `Project.CurrentPeriod` замість `AF_CurrentReportPeriod` (D-77) | скасовано D-51 |
| Реалізація силами AI (D-80…D-83) | критичний шлях — верифікація і перехід, не код |
| Рішення реалізації D-84…D-91 | ТЗ доведене до стану, з якого пишеться код |
| Наскрізна перевірка `tz/` проти `build/` — D-92…D-99 | прибрано чотири вимоги без механізму, закрито останні прогалини |
