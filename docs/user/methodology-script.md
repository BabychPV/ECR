# Скрипт методології: посібник еколога

Для інженера-еколога й методолога, що описує розрахунок викидів. Програмувати
вміти не треба: скрипт — це кілька десятків рядків тексту, схожих на формули в
Excel, але записаних по порядку й з поясненнями. Довідник за екранами —
`docs/user/user-guide.md`, сценарії за ролями — `docs/user/role-guide.md`,
адміністрування методологій — `docs/admin/admin-guide.md`. Сценарії перевірки —
`docs/build/TESTER-GUIDE.md`, група «Т».

> **Про приклади.** Кожен приклад скрипта в цьому файлі — повний і перевірений
> справжнім компілятором (`Ecr.Scripting`): він приймається без жодної
> помилки. Це робить автоматичний тест `UserGuideExamplesTests` (проєкт
> `tests/Ecr.Scripting.Tests`): він читає цей файл і компілює кожен блок. Тест
> перевіряє лише запис скрипта; чи є в системі ваші таблиці, колонки, одиниці й
> довідники, перевіряє редактор при збереженні (розділ 19.6).
> Окремі шматки, що не є цілими скриптами, у тексті не наводяться.
> Приклади з коментарем `// помилка: …` навмисно неправильні й показують, який
> код помилки дасть редактор. Бібліотечні приклади (розділ 15) позначено
> `// бібліотека: …` — це окремий файл, який підключає наступний приклад.
> Якщо додаєте приклад у цей посібник, ставте мітку блоку: `ecr` — повний
> скрипт, `ecr-lib` — бібліотека, `ecr-error` — навмисна помилка (перший рядок
> `// помилка: код`).
> Коди таблиць, колонок, довідників і одиниць у прикладах (`T3_00`, `Land_Fuel`, `LAND_FUEL`, `g_per_s`) — умовні: у вашій
> системі вони свої, і редактор перевірить їх при збереженні.

## 1. Що таке скрипт методології

**Методологія** — це спосіб порахувати викиди з даних документа. Версія
методології з рушієм **Script** описується **одним текстом** — скриптом. У ньому
сказано:

1. **з яких рядків** якої таблиці рахуємо (`rows from …`);
2. **які коефіцієнти** використовуємо (`const …`);
3. **які проміжні величини** потрібні (`var …`);
4. **що виходить** і в яких одиницях (`output …`);
5. за потреби — **коли рядок не рахувати** (`reject when …`) і **як рахувати по
   речовинах** (`foreach substance …`).

Скрипт читає **значення колонок рядка** (`row.Land_Fuel`) і пише **виходи**
(`output ECW_EC_tons_NOx : t = …`). Куди саме потрапить вихід, визначає колонка
шаблону типу `Calculated`, **код якої збігається з назвою виходу**: так результат
з'являється в сітці документа й у звітах.

Що **не** входить у текст скрипта й лишається окремо (ці екрани не змінилися):

| Що | Де |
|---|---|
| Тести методології (вхідні значення → очікувані виходи) | вкладка «Тести» |
| Обов'язкові колонки | вкладка «Обов'язкові колонки» |
| Прив'язка виходу до колонки шаблону | створюється автоматично при публікації за збігом кодів |
| Режим чисел (`Strict` / `Legacy`), календар, рівень трасування | властивості версії |

Інші версії тієї самої методології можуть лишатися «по-старому» (формули,
константи, категорії): обидва види працюють поруч, доки методологію не
перенесено. Версію зі скриптом у старому конфігураторі редагувати не можна.

### 1.1. Правила запису

- Кожна дія закінчується крапкою з комою `;`.
- Коментар — `// до кінця рядка` або `/* кілька рядків */`. Пишіть коментарі:
  через рік вони потрібні вам самим.
- Число пишеться з крапкою: `0.25`, `1e6`, `2.5E-3`. `.5` — помилка: пишіть
  `0.5`. Мінус перед числом — оператор: `-5`.
- Текст — в лапках `"…"` або `'…'`.
- Імена (констант, змінних, виходів): літери, цифри, підкреслення, не з цифри.
  `Kfuel` і `kfuel` — **одне** ім'я для скрипта (повтор — помилка).
- Зарезервовані слова, які не можна брати за імена: `import rows from where
  active when const var visible function output per if else foreach substance
  in reject skip true false null row period header key entry table param`.
- Порівняння — `==`, `!=`, `<`, `<=`, `>`, `>=`; логіка — `&&` (і), `||` (або),
  `!` (не). **Одинарне `=` у виразі — помилка**: це не порівняння.
- Степінь — `Pow(a, b)`, а не `a ^ b`. Залишок від ділення — `%`.
- «Якщо … то … інакше» у виразі — `умова ? а : б` (слова `if(...)` у виразі
  немає). «Належить набору» — `x in (a, b, c)`.
- Присвоювати вдруге не можна: кожна величина оголошується один раз. Потрібне
  інше значення — оголосіть іншу величину.

## 2. Перший приклад, рядок за рядком

```ecr
// Двигуни на бензині: викид NOx
rows from T3_00
    where row.Land_TypeFuel == entry("LAND_FUEL", "Gasoline")
    active when row.Land_Status == entry("LAND_GENERIC_EQUIPSTATUS", "Running");

const EF_NOx = 1.2;

var fuel   = row.Land_FuelConsumption;
var nox_g  = fuel * EF_NOx;

output ECW_EC_tons_NOx : t       = nox_g / 1000000;
output ECW_EC_gsec_NOx : g_per_s = nox_g / period.Seconds;
```

| Рядок | Що він каже |
|---|---|
| `// Двигуни…` | Коментар, на розрахунок не впливає. |
| `rows from T3_00` | Рахуємо рядки таблиці з кодом `T3_00`. |
| `where row.Land_TypeFuel == entry(…, "Gasoline")` | Беремо лише рядки, де в колонці «тип палива» вибрано запис «Gasoline» довідника `LAND_FUEL`. |
| `active when row.Land_Status == entry(…, "Running")` | Серед них «діючими» вважаємо лише ті, що в статусі «Running». Решта — «неактивні»: їх не рахують, але в перегляді видно, чому. Закінчується речення `;`. |
| `const EF_NOx = 1.2;` | Коефіцієнт: константа з іменем і значенням. |
| `var fuel = row.Land_FuelConsumption;` | Проміжна величина «fuel»: значення колонки поточного рядка. Колонка обов'язкова: якщо в рядку її взагалі немає — помилка «немає входу»; якщо комірка є, але порожня — значення `null` (див. розділ про поле рядка). |
| `var nox_g = fuel * EF_NOx;` | Друга проміжна величина: добуток. Рядки виконуються **згори вниз**; користуватися можна лише тим, що оголошено вище. |
| `output ECW_EC_tons_NOx : t = …` | **Результат.** Назва виходу = код колонки `Calculated` у таблиці; `t` — одиниця (тонни). Одиниця має існувати в довіднику одиниць. |
| `output ECW_EC_gsec_NOx : g_per_s = …` | Ще один вихід. `period.Seconds` — кількість секунд у розрахунковому періоді. |

Це **весь** скрипт. Збережіть його в редакторі (розділ 20) — він одразу
перевіриться, а справа можна подивитись числа на справжньому документі.

## 3. Вибір рядків: `rows from … where … active when …`

Скрипт без `rows from` не рахує нічого (помилка `missingRows`). Одна таблиця —
одне речення:

```ecr
rows from T3_00;
var fuel = row.Land_FuelConsumption;
output ECW_EC_tons_NOx : t = fuel * 1.2 / 1000000;
```

Кілька таблиць однієї форми, відбір за значеннями, неактивні рядки:

```ecr
rows from T3_00, T3_01
    where row.Land_TypeFuel in (entry("LAND_FUEL", "Gasoline"), entry("LAND_FUEL", "Diesel"))
       && row.Land_Remark == null
    active when row.Land_Status != entry("LAND_GENERIC_EQUIPSTATUS", "Stopped");

var fuel = row.Land_FuelConsumption;
output ECW_EC_tons_NOx : t = fuel * 1.2 / 1000000;
```

Правила:

- Для кожної таблиці — **не більш ніж одне** речення; різні таблиці можна
  розкласти по різних реченнях (з різними умовами). Одна таблиця у двох
  реченнях — помилка `duplicateTable`.
- Таблицю можна назвати з шаблоном: `rows from AirTemplate.T3_00`. Це потрібно,
  лише якщо код таблиці є в кількох шаблонах (інакше `ambiguousTable`).
- В умовах `where` і `active when` дозволено: `row.Колонка == значення`,
  `row.Колонка != значення`, `row.Колонка in (значення, значення)`, а також
  `&&`, `||`, `!` і дужки. **Значення** — це текст в лапках,
  `entry("ДОВІДНИК", "КОД")` або `null` («порожньо»). Порівнюється **текст**
  клітинки, з урахуванням регістру; число пишіть як текст: `row.Land_Class == "3"`.
  Колонки, якої немає в таблиці, відповідає «порожньо».
- Спочатку діє `active when`: рядки, де умова хибна, — **неактивні**. Потім
  `where` вибирає з активних ті, що рахуються. Без `active when` ніхто не
  виключається, без `where` рахуються всі активні.
- Умови тут **простіші**, ніж у решті скрипта: арифметики, функцій і `?:` немає.
  Складніше «рахувати чи ні» — через `reject when` (розділ 9).

Вибір запису довідника — `entry("КОД_ДОВІДНИКА", "КОД_ЗАПИСУ")`; такий запис
мусить існувати (інакше `unknownRegistryEntry` при збереженні). Він годиться
також і у виразах — як ідентифікатор запису:

```ecr
rows from T3_00;
var isGasoline = row.Land_TypeFuel == entry("LAND_FUEL", "Gasoline") ? 1 : 0;
output ECW_Flag : one = isGasoline;
```

## 4. Входи: колонки поточного рядка

Колонка рядка читається як `row.КодКолонки`:

```ecr
rows from T3_00;
var hours   = row.Land_RunningHoursMonthly;   // обов'язкова
var comment = row.Land_Note?;                  // необов'язкова: порожня -> null
var shift   = row.Land_ShiftCount? ;
output ECW_Hours : h = hours;
```

- **`row.X`** — обов'язкова колонка. Розрізняються три стани: значення є — береться
  воно; комірка є, але порожня, — `null` без помилки (так само, як у старих
  методологіях на формулах: вираз із `null` просто не дає значення); запису
  комірки в рядку немає зовсім — помилка `#ARG` («не вистачає входу»), рядок
  потрапляє в перегляд із позначкою «missing inputs», а у звіті про рядок
  названо, чого бракує. Якщо жодне значення рядка не вдалося порахувати,
  у «missing inputs» потрапляють і порожні, і відсутні обов'язкові колонки.
  Потрібна саме помилка на порожній комірці — перевірте явно: `row.X == null`.
- **`row.X?`** — необов'язкова: порожня дає `null` (без помилки). Знак `?`
  пишеться **упритул** до імені. Умовний вираз пишеться з пробілом:
  `row.X ? a : b`.
- Імена колонок — як у шаблоні; регістр букв при пошуку не важливий.

**Вибір із довідника.** Якщо в колонці обрано запис довідника, `row.X` дає його
значення «як бачить розрахунок» (число чи текст), а `key(row.X)` — **ключ запису**
(потрібен, щоб передати запис у функції довідників, розділ 17):

```ecr
rows from T3_00;
var fuelKey = key(row.Land_TypeFuel);
var density = REGFIELD(fuelKey, "Density");
output ECW_FuelDensity : kg_per_m3 = density;
```

**Місячні колонки.** Якщо в шаблоні дані за рік лежать у колонках по місяцях
(`Land_Hours_M01 … Land_Hours_M12`, або через псевдонім місячного входу), читайте
потрібний місяць **індексом**:

```ecr
rows from T3_00;
var hours = row.Land_Hours[period.Month];       // місяць розрахункового періоду
var jan   = row.Land_Hours[1];                   // конкретний місяць
var opt   = row.Land_Extra?[period.Month];       // необов'язковий
output ECW_Hours : h = hours + jan;
```

Місяць має бути цілим від 1 до 12, інакше результат `#ARG`. Так колонки-«містки»
шаблону (вибір за місяцем) більше не потрібні.

Редактор допомагає: після `row.` у підказках місячна колонка (`Land_Hours_M01 …
Land_Hours_M12`) стоїть **одним пунктом** `Land_Hours` і вставляється відразу як
`Land_Hours[period.Month]` — залишається лише поправити місяць, якщо треба інший.
Так само підказується псевдонім місячного входу таблиці.

## 5. Константи й таблиці коефіцієнтів

Число, текст чи так/ні — з одним іменем на весь скрипт. Одиницю можна вказати:

```ecr
rows from T3_00;
const k_diesel = 0.84;
const label = "Diesel";
const strict_mode : kg = 5;
const enabled = true;
var x = row.Land_FuelConsumption * k_diesel;
output ECW_X : t = x / 1000;
```

**Таблиця коефіцієнтів** (мапа): значення, що залежать від ключа — пори року,
типу палива, речовини. Рівнів вкладення може бути кілька:

```ecr
rows from T3_00;

const EF_by_fuel = { Gasoline: 1.2, Diesel: 1.4, Gas: 0.3 };

const EF_gsec = {
    Summer: { NOx: 1.2, CO: 0.3 },
    Winter: { NOx: 1.4, CO: 0.3 },
};

const DaysIn = { 1: 31, 2: 28, 3: 31 };

var season = period.Month >= 4 && period.Month <= 9 ? "Summer" : "Winter";
var nox    = EF_gsec[season].NOx;           // ключ із величини, назва — поруч
var co     = EF_gsec[season]["CO"];          // те саме іншим записом
var nox2   = EF_gsec[season, "NOx"];         // кілька ключів у одних дужках
var fixed  = EF_gsec.Summer.NOx;             // обидва ключі відомі наперед
var days   = DaysIn[period.Month];           // число-ключ

output ECW_NOx : g_per_s = nox * row.Land_FuelConsumption / period.Seconds;
```

Правила таблиць:

- Ключ — слово, текст в лапках (`"0301"`) або число. Ключі порівнюються **як
  текст**, регістр важливий: число `1` і ключ `1` збігаються, `Summer` і `summer` —
  ні. Кінцева кома після останнього запису дозволена.
- Звернутися до мапи **без ключа** не можна: `var x = EF_gsec;` — помилка
  `mapNotScalar`; так само, якщо ключів замало. Забагато ключів — `indexOnNonMap`.
- **Ключа немає в таблиці.** Якщо ключ у скрипті записано буквально
  (`EF_gsec.Autumn.NOx`), це помилка компіляції `unknownMapKey` — ви побачите її
  відразу. Якщо ключ береться з величини (`EF_gsec[season]`), перевірити наперед
  нічого, і під час розрахунку значення стає помилкою `#N/A` («немає
  такого запису»). Порожній ключ (`null`) дає теж `#N/A`.
- Повторений ключ в одному рівні — помилка `duplicateMapKey`.
- Константи **не мають вікон дат**. Нове значення з нової дати — це **нова
  версія методології** (з новим авторством і датою чинності).
  Лише якщо цього потребує перенесення старих методологій, умову за датою
  записують через `period.EndKey` (розділ 16).

Велику таблицю зручно правити **сіткою**, а не текстом (розділ 20).

## 6. Проміжні величини: `var` і `visible var`

`var` — величина для подальших рядків скрипта; у результати вона не потрапляє:

```ecr
rows from T3_00;
var hours = row.Land_RunningHoursMonthly;
var fuel  = row.Land_FuelConsumption;
var idle  = hours == 0 && fuel == 0;
output ECW_NOx : t = idle ? 0 : fuel * 1.2 / 1000000;
```

`visible var` — теж проміжна, але її **видно в результатах** (їх показують
у розгортанні рядка й у звітах про перерахунок). Одиниця **обов'язкова**:

```ecr
rows from T3_00;
visible var fuel_t : t = row.Land_FuelConsumption / 1000;
output ECW_NOx : t = fuel_t * 1.2;
```

Видима величина без одиниці — помилка `visibleNeedsUnit`.

Область видимості: величина видна **нижче** свого оголошення (раніше —
`forwardReference`), у блоці `{ … }` оголошене в блоці зовні невидиме. Ім'я в блоці
не може збігатися з видимим зовнішнім. `const` і `function` видно скрізь,
незалежно від місця.

## 7. Виходи й одиниці

```text
output КодВиходу : одиниця = вираз;
```

- **Код виходу** — ім'я колонки типу `Calculated` у таблиці з `rows from`
  (або `КодВиходу_M01 … _M12` для місячних колонок). При публікації система сама
  створює відсутні прив'язки «вихід → колонка». Якщо жоден вихід не вдалося
  прив'язати, публікацію відхилено (`noBoundOutput`): методологія нічого б не
  записала.
- Код виходу пишуть латиницею: літери, цифри й `_`, перша — літера, не довше 64
  знаків. Інакше — `invalidOutputCode` при збереженні.
- **Одиниця** — код з довідника одиниць (`t`, `kg`, `g_per_s`…). Невідому система
  відхилить: `unknownUnit`.
- Одиниці **перевіряються**: додавати «тонни» до «кілограмів» без `CONVERT` не
  можна (`unitMismatch`) — так само сувора ця перевірка й для старих формул.
- Результат округлюється за **шкалою колонки** шаблону; в усіх розрахунках до
  округлення число зберігає повну точність.
- Код виходу після оголошення можна читати як змінну:
  `output A : t = x; var b = A * 2;`.
- Коди виходів унікальні без урахування регістру. Єдиний виняток: той самий код
  з тією ж одиницею можна оголосити в гілках `if` і `else` (розділ 8).
- Скрипт-бібліотека (розділ 15) виходів не має (`outputInLibrary`).

## 8. Умови

**У виразі** — `умова ? якщо_так : якщо_ні`, у т. ч. вкладені:

```ecr
rows from T3_00;
var load   = row.Land_Load;
var factor = load > 0.8 ? 1.3 : (load > 0.5 ? 1.1 : 1);
var kind   = row.Land_Kind? == null ? "unknown" : "known";
output ECW_X : t = row.Land_FuelConsumption * factor / 1000;
```

**Блоком** `if / else` — коли від умови залежать цілі групи дій:

```ecr
rows from T3_00;
var hours = row.Land_RunningHoursMonthly;
if (hours == 0) {
    output ECW_NOx : t = 0;
} else if (hours < 10) {
    var part = row.Land_FuelConsumption * 0.5;
    output ECW_NOx : t = part * 1.2 / 1000000;
} else {
    output ECW_NOx : t = row.Land_FuelConsumption * 1.2 / 1000000;
}
```

- Умова — у круглих дужках, дії — у фігурних, навіть одна.
- Умова мусить бути **істина або хиба**. Якщо вона виявиться помилкою чи
  порожньою (наприклад, не було входу), жодна гілка не виконується, а **кожен**
  вихід, що в них записаний, дістає помилку (`#VALUE`, `#NULL` або код тієї
  помилки) — а не тихий нуль.
- Той самий вихід у гілках `if` і `else` — нормально (з однаковою одиницею).
- `const` усередині блоку писати не можна; змінні блоку поза ним невидимі.
- Належність до набору в умові: `row.Land_Class in (1, 2, 3)`.

## 9. Відхилити рядок: `reject when`

Якщо дані рядка такі, що рахувати не можна, — відхиліть його. Рядок не
рахується, а проблема записується як «рядок відхилено правилом»:

```ecr
rows from T3_00;
reject when row.Land_FuelConsumption < 0;
reject when row.Land_TypeFuel == entry("LAND_FUEL", "Unknown");
output ECW_NOx : t = row.Land_FuelConsumption * 1.2 / 1000000;
```

⚠ Рядок **проходить**, лише якщо умова — точно «хиба». Якщо умова істинна, **або
порожня, або помилка** (наприклад, у рядка немає колонки
`row.Land_FuelConsumption`), рядок відхиляється. Тому пишіть умови, що завжди
мають певний результат, і дивіться на вкладку «Перегляд»: відхилені рядки там
позначені `rejected`.

### 9a. Довідник на дату рядка: `registry as of`

Типово всі читання довідників (`REGFIND`, `REGONE`, `REGFIELD`, `REGSUM`,
`REGCOUNT`, `REGAVG`, `REGMIN`, `REGMAX`, шляхи `ROW.<lookup>.<поле>`) бачать
версію, чинну **в останній день періоду** документа. Коли кожен рядок — окрема
подія зі своєю датою (наприклад, подія факела з AF), а довідник має кілька
версій у межах періоду, напишіть одне речення після `rows from`:

```ecr
rows from INT_SG_EVENTS;
registry as of row.EVENT_START;
var split  = REGFIELD(REGFIND("LP_SOUR_SPLIT", 1), "COEF");   // версія, чинна на дату події
var season = asof.Month >= 4 && asof.Month <= 9 ? "Summer" : "Winter";
output V_S1 : m3 = row.TOTAL * split;
```

- Вираз обчислюється **на кожен рядок** і мусить давати дату (зазвичай колонка
  дати рядка, `$start` події). Час події записано в колонку вже в поясі проєкту,
  тож дата — це календарний день у поясі проєкту.
- Усі читання довідників цього рядка бачать версію, чинну **на цю дату**, у
  місячному й річному документі однаково (річний з колонками місяців теж).
- `asof.Date`, `asof.Month`, `asof.Year` — дата рядка; у річному документі
  `period.Month` не має сенсу, беріть `asof.Month`.
- Дата порожня або помилкова → рядок **відхилено** з причиною
  «registry as of date is empty»; дата поза періодом документа → відхилено з
  причиною «registry date … outside the document period». Нуля замість
  числа не буде.
- Без речення все як і раніше: знімок на кінець періоду.
- Речення одне на скрипт, не в бібліотеці. Повідомлення компілятора:
  `duplicateRegistryAsOf` (друге речення), `registryAsOfNotDate` (число, текст,
  true/false чи null замість дати), `registryAsOfWithoutRegistries` (скрипт не
  читає жодного довідника — речення нічого не змінює).
- Перерахунок після зміни версії довідника йде за роком (довідник × рік): нова
  версія з березня перераховує всі відкриті документи цього року, що читають
  довідник.
- «Перегляд» рахує так само, як розрахунок: рядки по різні боки межі версій
  показують різні значення.

## 10. Речовини: `foreach substance`, `per S`, `skip when`

Коли для рядка треба порахувати кілька речовин за однією схемою, оголошують цикл
по кодах речовин, а вихід записують **«по речовині»** (`per S`):

```ecr
rows from T3_00;

const EF = { "0301": 1.2, "0304": 0.3, "0337": 7.5 };

var fuel = row.Land_FuelConsumption;

foreach substance S in ("0301", "0304", "0337") {
    skip when S.code == "0337" && fuel == 0;
    output ECW_EC_tons per S : t = fuel * EF[S.code] / 1000000;
}
```

- `foreach substance S in ("код", "код"…)` — коди з довідника речовин (невідомий код —
  `unknownSubstance` при збереженні). `S` — ім'я змінної речовини; для кожної
  речовини блок виконується окремо.
- `S.code` — код поточної речовини **як текст** (інших властивостей у `S` немає).
- `output … per S : …` записує результат із позначкою речовини. **Усередині**
  циклу вихід без `per S` — помилка `outputNeedsPer`; **поза** циклом `per S` —
  помилка `outputOutsideSubstanceLoop`.
- `skip when умова;` — пропустити цю речовину для цього рядка (вона просто не
  рахується, у розрахунку лишається запис «речовина не застосовна»). Писати
  можна лише **безпосередньо** в тілі циклу, не в `if` (`skipOutsideSubstanceLoop`).
- Вкладений `foreach substance` заборонено (`nestedSubstanceLoop`).
- Змінні, оголошені всередині циклу, існують лише для однієї речовини.

## 11. Повтори: `foreach Х in (…)` і `{X}`

Коли треба записати те саме для кількох чисел (301, 304, 330), не копіюйте
рядки вручну. Блок `foreach` на етапі перевірки **розгортається в окремі рядки**
(жодного «циклу» під час розрахунку немає):

```ecr
rows from T3_00;
const EF = { s301: 1.2, s304: 0.3, s330: 0.1 };
var base = row.Land_FuelConsumption;

foreach S in (301, 304, 330) {
    output ECW_EC_gsec_{S} : g_per_s = base * EF["s{S}"] / period.Seconds;
}
```

Правила розгортання:

- Усередині блоку `{S}` у назві (або в тексті в лапках) замінюється на значення:
  `ECW_EC_gsec_{S}` стає `ECW_EC_gsec_301`, `"s{S}"` — `"s301"`. Окрема `S`
  стає самим значенням (там `301`).
- Значення — числа або тексти. Якщо після підстановки вийшло не-ім'я
  (`"a b"`) — помилка `foreachNameNotIdentifier`.
- Те, що оголошено всередині, лишається **у зовнішній області**: імена не можуть
  повторюватися (`var v{N}` з однаковими `N` — `duplicateName`).
- Вкладати можна до 3 рівнів, усього не більше 2000 розгорнутих операторів і
  200 000 розгорнутих лексем (`foreachTooLarge`; повідомлення прямо називає, яку з трьох меж перевищено). `foreach` можна писати й усередині `foreach substance`.

Різниця з `foreach substance`: `foreach substance` — це справжній цикл за
речовинами (виходи «по речовині»); `foreach X in (…)` — лише скорочення запису.

## 12. Власні функції

Зручно, якщо та сама формула вживається в кількох місцях:

```ecr
rows from T3_00;

const k_heat = 42;

function heat(fuel, k) = fuel * k / 1000;
function is_summer() = period.Month >= 4 && period.Month <= 9;

var summer = is_summer();
var q      = heat(row.Land_FuelConsumption, k_heat);
output ECW_Heat : gj = summer ? q : q * 1.1;
```

- Тіло — **один вираз** після `=`. Параметри — імена, видимі лише всередині.
- Функція бачить `const`, інші функції, `row`, `period`, `header` і члени
  імпортованих бібліотек, але **не бачить** `var` і `output`.
- Рекурсія (функція викликає сама себе, навіть через іншу) — `recursiveFunction`.
- Кількість аргументів при виклику мусить збігатися з оголошеною (`argumentCount`).
- Агрегат (розділ 13) у тілі функції заборонено (`aggregateNotAllowedHere`).

## 13. Читання інших таблиць: `table` і агрегати

Інколи потрібні дані не лише рядка, що рахується, а й іншої таблиці **того самого
документа й періоду** (суми, найбільше, кількість). Спочатку оголосіть
**псевдонім** таблиці, потім читайте її колонки **всередині агрегату**:

```ecr
rows from T3_00;
table Gtu = T10_03;

var no2   = Max(Gtu.Land_Measure_GTU1_301 where Gtu.Land_GTU_MonthNo == period.Month);
var hours = Sum(Gtu.Land_Hours where Gtu.Land_Unit == row.Land_Unit);
var load  = Avg(Gtu.Land_Load);
var low   = Min(Gtu.Land_Load where Gtu.Land_Hours > 0);
var name  = First(Gtu.Land_Name where Gtu.Land_Unit == row.Land_Unit);
var n     = Count(Gtu where Gtu.Land_Hours > 0);
var has   = Any(Gtu where Gtu.Land_Unit == row.Land_Unit);
var jan   = Sum(Gtu.Land_Hours[period.Month]);

output ECW_GTU_Hours : h = has ? hours : 0;
```

| Агрегат | Що дає | Якщо рядків немає |
|---|---|---|
| `Sum(Т.Кол where …)` | сума значень | `0` |
| `Min`, `Max` | найменше, найбільше | порожньо (`null`) |
| `Avg` | середнє | порожньо |
| `First` | значення першого відповідного рядка | порожньо |
| `Count(Т where …)` | кількість рядків, що пройшли умову | `0` |
| `Any(Т where …)` | «так», якщо хоч один рядок пройшов | «ні» |

- `where` — необов'язкова умова відбору рядків **тієї таблиці**. Усередині: `Т.Кол` —
  клітинка рядка-кандидата, `row.X` — поточний рядок, що рахується; доступні
  `const`, `var`, функції, `period`.
- Значення `null` пропускається; помилка в значенні дає цю помилку результатом.
  Нечислове значення в `Sum`/`Avg` — `#VALUE`.
- `Т.Кол` **поза** агрегатом — помилка `tableColumnOutsideAggregate`. Усередині
  `Sum/Min/Max/Avg/First` значення мусить читати **рівно одну** таблицю
  (`aggregateNeedsTable`, `aggregateManyTables`). Вкладений агрегат над **іншою**
  таблицею можна, над тією самою — `nestedAggregateSameTable`. Не можна в
  `where`/`active when` речення `rows` і в тілі функції.
- `Min(a, b)` і `Max(a, b)` з **двома значеннями без `where`** — це звичайні
  функції (розділ 17), а не агрегати.
- Таблиця може бути й тією самою, з якої беруться рядки: `table Self = T3_00;`.
- Якщо поточний рядок лежить на копії аркуша, беруться рядки з тієї ж копії (немає —
  з оригіналу).
- Зміна в таблиці-джерелі перераховує й методологію, що її читає.

## 14. Читання результатів іншої методології

Колонка типу `Calculated` у вашій таблиці, на яку **вже** налаштовано вихід
**іншої** методології, читається як звичайна колонка — жодного нового синтаксису:

```ecr
rows from T5_00;

// сумарний викид NOx із таблиці джерел, порахований методологією-постачальником
table Sources = T3_00;
var noxTotal = Sum(Sources.ECW_EC_tons_NOx where Sources.Land_Unit == row.Land_Unit);

output Unit_NOx_Share : one = noxTotal == 0 ? 0 : row.ECW_EC_tons_NOx / noxTotal;
```

- Значення — те, що користувач бачить у сітці, але з **поточного** прогону.
- Система сама розкладе методології в потрібному порядку: спочатку та, чий
  результат читають, потім та, що читає.
- Результату для рядка немає: `row.Код` — помилка `#ARG`, `row.Код?` — порожньо.
- Читати **власні** виходи не можна. Цикл «A читає B, B читає A» (напряму чи
  ланцюгом) блокує публікацію.
- Колонка `Calculated`, до якої ніхто не прив'язаний, нічого не дає: читати нема
  чого (`unknownColumn`).
- Якщо цикл з'явився вже після публікації (хтось додав нову прив'язку виходу до
  колонки), документ не рахується **зовсім** — часткового результату не буде:
  помилка `scriptResultCycle` (`ECR-CALC-0422`). Розірвіть цикл і перерахуйте.

Якщо потрібно **спільне** обчислення, а не чужий результат, — виносьте його в
бібліотеку (розділ 15).

### 14.1. Дані документа-джерела (склад газу HSE400) і автоматичний перерахунок

Дані з **документа-джерела** (наприклад, склад газу з документа HSE400) скрипт читає з **довідника**, який
наповнює цей документ: зв'язка джерела (екран «Зв'язки документів-джерел») підміняє рядки довідника
`LAND_HSE400_COMPOSITION` значеннями документа. Окремого синтаксису немає — це звичайні функції довідників
(розділ 17) і період (розділ 16):

```ecr
rows from T9_04;

// склад газу за поточний рік і місяць документа; потік береться з тексту палива за словником потоків
foreach substance S in ("H2S") {
    var stream = REGFIELD(REGFIND("LAND_HSE400_STREAM", row.Land_TypeFuelOrStream), "PREFIX");
    var indicator = REGFIELD(REGFIND("LAND_HSE400_SUBSTANCE", CURRENT_SUBSTANCE()), "INDICATOR");
    var mass = REGFIELD(REGFIND("LAND_HSE400_COMPOSITION", period.Year, period.Month, stream, indicator), "VALUE");
    output Gas_Mass per S : kg = mass * row.Land_Volume;
}
```

- Це **той самий** вираз, що формульні методології Land (`C11_01`, `C11_02`, `C11_10`, `C12_01`, `C12_03`) мають у фрагменті
  `@CompositionMass`; перетворювач переносить його в скрипт без змін (`[Period].Sequence` стає `period.Month`).
- Якщо зв'язка в стані «лише затверджені», незатверджений місяць джерела **не дає даних**: `REGFIND` повертає
  «немає запису» (`#N/A`), рядок лишається без результату — так само, як у формульних методологій.
- **Перерахунок.** Після правки документа-джерела система сама ставить перерахунок документів-споживачів, зокрема тих, чия
  методологія — скрипт, і тих, що читають **результати** таких методологій (розділ 14), навіть в інших документах. Вручну
  перераховувати не потрібно.
- Публікація скрипта, через читання довідника чи чужих результатів якого документ почав би залежати від самого себе
  (наприклад, скрипт пише в документ-джерело того довідника, який читає), відхиляється з повідомленням про цикл залежностей
  документів і шляхом кодами `ШАБЛОН → ДОВІДНИК → … → ШАБЛОН`. Те саме — для перемикання версії на скрипт.
  Те саме правило діє й для **формульних** версій методологій: публікація, що замкнула б такий цикл, відхиляється.
- **Що саме перераховується.** Скрипт, який читає довідник за поточним місяцем (`period.Year` разом із `period.Month` у ключі
  `REGFIND`), перераховується лише для того ж місяця документа-джерела; з літеральним місяцем (`period.Year, 10`) — лише
  для цього місяця року; з одним `period.Year` — для всього року. Якщо система не може довести обсяг (ключ збережено в змінній,
  `period.Year - 1`, довідник читається ще й через `entry(...)`, скрипт підключає бібліотеку через `import`), вона перераховує
  документи-споживачі за будь-який період — зайвий перерахунок безпечніший за пропущений.
- **Версія рівня Module (HSE400)** не має перегляду на документі: вкладка «Перегляд» вимкнена з поясненням, бо набір аргументів
  складає модуль розрахунку, а не рядки скрипта. Результат звіряйте розрахунком документа.

## 15. Бібліотеки: `import`

**Бібліотека** — методологія виду `Library`: у ній лише `const`, `function` і
`var`, без `rows` і `output`. Її підключають кілька методологій, щоб не
дублювати спільні коефіцієнти й формули.

```ecr-lib
// бібліотека: Common
const HOURS_PER_DAY = 24;
const SEC_PER_HOUR = 3600;

function per_second(x) = x / (period.Days * HOURS_PER_DAY * SEC_PER_HOUR);

var summer = period.Month >= 4 && period.Month <= 9;
```

```ecr
import Common;

rows from T3_00;

var rate = Common.per_second(row.Land_FuelConsumption);
output ECW_Rate : g_per_s = Common.summer ? rate * 1.2 : rate * 1.4;
```

- `import Код;` — на самому **початку** файла, до решти (після інших рядків
  — помилка). Код — код методології-бібліотеки.
- Звернення — `Бібліотека.Ім'я`: до `const`, `var` і `function` бібліотеки.
  Мапу з бібліотеки індексують так само: `Common.EF[season].NOx`.
- Використовується версія бібліотеки, чинна на **дату кінця періоду**.
- Бібліотека може підключати іншу бібліотеку; цикл заборонено, глибина — до 8.
- Помилки: бібліотеки немає (`unknownImport`), у ній немає такого імені
  (`unknownImportMember`), це не бібліотека зі скриптом (`libraryNotScript`),
  `rows`/`output` у бібліотеці (`rowsInLibrary`, `outputInLibrary`).
- `var` бібліотеки обчислюється в контексті **вашого** рядка: його `row`,
  `period` і поточна речовина.
- Версія бібліотеки публікується **без золотого набору** (у неї немає виходів, тож очікувань
  нема чим задати; D-556): компіляція й статичні перевірки лишаються, а її поведінку
  перевіряють золоті набори методологій, що її імпортують.

### 15.1. Змінна імпортера: `param`

Бібліотека може **читати змінну того, хто її підключає**. Для цього в ній
оголошують `param Ім'я;` (лише в бібліотеці — у звичайному скрипті це помилка
`paramOutsideLibrary`). Далі `Ім'я` вживається як звичайна змінна.

```ecr-lib
// бібліотека: Common
param Category;

const EF = { Summer: 1.2, Winter: 1.4 };

var factor = EF[Category];
```

```ecr
import Common;

rows from T3_00;

var Category = key(row.Land_Season);
output ECW_Rate : g_per_s = row.Land_FuelConsumption * Common.factor;
```

- Значення `param` — змінна **імпортера з тим самим ім'ям**, видима в місці
  звернення: у `foreach substance` змінна блоку важливіша за верхню.
- Якщо в імпортера такої змінної немає, значення — порожнє (`null`); пошук у
  мапі за порожнім ключем дає `#N/A`.
- Виняток для `Category`: усередині `foreach substance`, де є змінна
  `SubstanceCategory`, бібліотека бачить саме її — так, як це було в старих
  методологіях з категорією речовини.
- Величини бібліотеки, що читають `param`, запам'ятовуються окремо для
  рядка й для кожної речовини, тому різні речовини дають різні значення.

## 16. Період і шапка документа

| Запис | Що це |
|---|---|
| `period.Month` | номер місяця періоду, 1–12 |
| `period.Year` | рік періоду |
| `period.Days` | кількість днів у періоді |
| `period.Hours` | кількість годин у періоді |
| `period.Seconds` | кількість секунд у періоді |
| `period.Start`, `period.End` | початок і кінець періоду (дати) |
| `period.EndKey` | дата кінця періоду числом `РРРРММДД` (напр. `20260930`) |
| `header.Ім'я` | поле шапки документа |

```ecr
rows from T3_00;

const EF_OLD = 1.3;
const EF_NEW = 1.1;

var ef     = period.EndKey >= 20270101 ? EF_NEW : EF_OLD;
var region = header.Land_Region;
var share  = period.Days / 30;

output ECW_NOx : t = row.Land_FuelConsumption * ef / 1000000 * share;
```

Невідома властивість `period` (наприклад, `period.Week`) — помилка `unknownName`
з переліком можливих.

Не вшивайте нове значення коефіцієнта в умову за `period.EndKey` з власної
ініціативи: для цього є **нова версія методології** з датою чинності (розділ 5).
`EndKey` потрібен переважно для переносу старих методологій, що вже мали
історичні вікна дат.

## 17. Вбудовані функції

Імена **чутливі до регістру** (`Pow`, не `POW`; на помилку редактор підкаже
правильне написання), кількість аргументів строга. Перелік узято з каталогу
діалекту методологій (`DialectCatalog`).

| Функція | Що робить |
|---|---|
| `Abs(x)` | модуль числа |
| `Acos(x)`, `Asin(x)`, `Atan(x)` | обернені тригонометричні (радіани) |
| `Cos(x)`, `Sin(x)`, `Tan(x)` | тригонометричні (радіани) |
| `Ceiling(x)` | округлення вгору до цілого |
| `Floor(x)` | округлення вниз до цілого |
| `Truncate(x)` | відкидання дробової частини |
| `Round(x, n)` | округлення до `n` знаків (рівно два аргументи) |
| `Exp(x)` | `e` у степені `x` |
| `Log(x, основа)` | логарифм за основою (рівно два аргументи) |
| `Log10(x)` | десятковий логарифм |
| `Ln(x)` | натуральний логарифм (лише режим `Strict`) |
| `Pow(x, y)` | `x` у степені `y` |
| `Sqrt(x)` | квадратний корінь |
| `Sign(x)` | знак числа: −1, 0 або 1 |
| `IEEERemainder(x, y)` | залишок від ділення за стандартом IEEE |
| `Max(a, b)`, `Min(a, b)` | більше / менше з двох (рівно два аргументи) |
| `ifs(умова1, значення1, …)` | перша істинна умова (лише режим `Strict`) |
| `CONVERT(значення, "з", "до")` | перерахунок між одиницями; **єдиний** спосіб змінити одиницю (лише `Strict`) |
| `SUBSTANCE("код")` | значення величини, названої кодом речовини; для старих формул, у скриптах зазвичай не потрібна (лише `Strict`) |
| `CURRENT_SUBSTANCE()` | код речовини поточного проходу `foreach substance` |
| `SUBSTANCE_APPLICABLE(…)` | чи застосовна речовина до рядка за довідником застосовності |
| `CONTAINS(текст, фрагмент)` | чи містить текст фрагмент (з урахуванням регістру; порожній текст — ні) |
| `StripSpaces(текст)` | текст без жодного пробільного символу; лише скрипт (не діалект старих формул). Так перетворювач читає ключ категорії, як старий рушій; `null` і не-текст лишаються як є |
| `REGFIND(довідник, ключ…)` | запис довідника за ключем |
| `REGONE(довідник, умова)` | єдиний запис, що задовольняє умову |
| `REGFIELD(запис, "Поле")` | значення поля запису довідника |
| `REGSUM`, `REGAVG`, `REGMIN`, `REGMAX (довідник, умова, вираз)` | сума, середнє, найменше, найбільше за записами довідника |
| `REGCOUNT(довідник, умова)` | кількість записів, що задовольняють умову |

Лише в режимі версії `Strict` доступні `Ln`, `ifs`, `CONVERT` і `SUBSTANCE`; у
режимі `Legacy` (він існує, щоб відтворювати числа старої системи) вони
відхиляються повідомленням `functionNotAllowedInMode`. Решта функцій таблиці,
зокрема `CONTAINS`, `CURRENT_SUBSTANCE`, `SUBSTANCE_APPLICABLE` і функції
довідників `REG…`, працюють в обох режимах. Умовні конструкції `if` та `in` — не функції: вони
пишуться як `? :` та `x in (…)`.

**Поле рядка довідника — `ROW.<поле>`** (D-580). В умові `REGONE`/`REGCOUNT` і в
умові та виразі `REGSUM`/`REGAVG`/`REGMIN`/`REGMAX` (з другого аргументу)
`ROW.<поле>` — поле запису, який перебирає функція; `ROW.<посилання>.<поле>` —
поле запису, на який той посилається. Ліворуч — `ROW`, праворуч — будь-який
вираз скрипта (змінна, `row.X`):

```ecr
rows from INT_SG_EVENTS;
var stream = REGONE("STREAM", ROW.LEGACY_ID == row.GAS_COMPOSITION_ID);
var gas_case = REGFIND("STREAM_CASE", stream, row.STREAM_TYPE);
output H2S : one = REGSUM("GAS_COMPOSITION", ROW.CASE == gas_case && ROW.COMPONENT == REGFIND("COMPONENT", "H2S"), ROW.MOL_PCT);
```

- Жоден запис не підійшов — `REGSUM` дає `0`, `REGCOUNT` — `0` (так стара система
  читала відсутній компонент складу: «порожньо → 0»). `REGONE` без запису — `#N/A`.
- Умова `ROW.<посилання> == <вираз без ROW>` першою частиною — швидкий пошук за
  індексом; інакше функція перебирає всі записи довідника (довго на великих).
- Поза цими функціями `ROW` — помилка `rowOutsideRegistryFunction`. Колонка
  поточного рядка документа — як і раніше `row.X` (мала літера).

Невідома функція — `unknownFunction`; якщо ви лише помилились у регістрі,
повідомлення підкаже правильне написання. Функції довідників для звичайної
методології потрібні рідко: більшість задач розв'язують `const`-таблицями.

```ecr
rows from T3_00;
var kg   = row.Land_FuelConsumption;
var t    = Round(kg / 1000, 3);
var big  = Max(t, 0.5);
var root = Sqrt(Pow(t, 2) + 1);
var sign = Sign(t - 1);
output ECW_Fuel : t = big + root + sign;
```

## 18. Що відбувається при помилках розрахунку

Помилка в скрипті — **значення**, а не аварія: вона поширюється далі й
показується в перегляді та звіті про рядок. Перегляд позначає такі рядки
(«step error», «missing inputs», «rejected»); решта рядків рахується як звичайно.

| Показ | Що означає | Типова причина | Що робити |
|---|---|---|---|
| `#ARG` | не вистачає входу | колонки `row.X` немає в рядку (порожня комірка дає `null`); немає результату іншої методології; місяць не в межах 1–12 | заповніть колонку або читайте її необов'язково (`row.X?`) |
| `#N/A` | у таблиці коефіцієнтів немає такого ключа | значення ключа `EF[fuel]` не записане в `const`; ключ порожній | додайте ключ у таблицю або поправте ключ |
| `#VALUE` | значення недопустиме для дії | текст у множенні; умова `if` не «так/ні»; власні функції вкладено надто глибоко (понад 32) | перевірте типи входів і умову |
| `#DIV/0` | ділення на нуль | знаменник дорівнює нулю | захистіть: `d == 0 ? 0 : x / d` |
| `#NULL` | порожнє значення там, де потрібне визначене | порожня умова в `if (…)` | перевірте порожність явно: `x == null` |
| `#REF` | запис довідника не знайдено | `entry(…)` вказує на неіснуючий запис | виправте код запису |

Вихід, обчислення якого дало помилку, **не записується** у результат, а рядок
позначається проблемою «step error» з описом першого збою. Якщо **жодне**
значення рядка не вдалося порахувати, а `output` у скрипті є, у перегляді буде
перелік обов'язкових колонок, яких не вистачає.

### 18.1. Чому в режимі Legacy ділення на нуль дає 0

Режим `Legacy` відтворює арифметику **старої системи**, щоб нові числа збігалися
з поточними звітами. Стара система після **кожного кроку** обчислення замінювала
нескінченність і «не число» (результат ділення на нуль, `Sqrt` від'ємного)
нулем. Тому в `Legacy` вираз `x / 0` дає `0`, а не `#DIV/0`; кожну таку заміну
записано в трасу розрахунку (позначка «masked»), щоб її можна було знайти.
Режим `Strict` показує справжню помилку `#DIV/0`. Режим — властивість
версії методології; змінює її адміністратор, не скрипт.

## 19. Повідомлення компілятора й що виправити

Помилки підкреслюються в редакторі й зібрані на вкладці «Проблеми»: код, рядок,
колонка. Наведено англійський текст повідомлення (інтерфейс показує переклад за
тим самим кодом) і що робити.

### 19.1. Синтаксис

| Код | Що написано в повідомленні | Що виправити |
|---|---|---|
| `unexpectedToken` | Unexpected '…' | зайвий або не на своєму місці символ чи слово; перевірте дужки, коми, `;` |
| `expected` | Expected …, found '…' | пропущено `;`, дужку, `=`, ім'я; або ім'я збігається з зарезервованим словом (`var row = …`) |
| `unterminatedString` | String is not closed | додайте закриваючу лапку |
| `unterminatedComment` | Comment is not closed | додайте `*/` |
| `invalidNumber` | Invalid number / out of the decimal range / too many significant digits | пишіть `0.5`, а не `.5`; число завелике; або в числі більше 28 значущих цифр, і значення мовчки змінилося б, тож скоротіть запис (хвостові нулі не рахуються) |
| `caretNotPower` | The '^' operator does not exist | степінь — `Pow(a, b)` |
| `assignInExpression` | Single '=' is an assignment | у порівнянні пишіть `==` |
| `tooLarge` | Script is too large | скрипт довший за 200 000 символів: винесіть спільне в бібліотеку. Текст довший за 1 000 000 знаків система не приймає взагалі (див. 19.7) |
| `tooDeep` | Expression nesting is too deep | вираз вкладено глибше 64 рівнів, або дерево виразу (разом із довгим ланцюгом `a + b + …`) глибше 500: розбийте його на `var` |

| Код | Повідомлення | Що виправити |
|---|---|---|
| `duplicateName` | The name '…' is already used | ім'я зайняте (регістр не враховується); у блоці — повторює зовнішнє ім'я; вихід двічі |
| `unknownName` | Unknown name '…' | помилка в імені або величину не оголошено; змінна блоку поза блоком; невідома властивість `period` |

| `functionNotAllowedInMode` | Function '…' is not available in Legacy numeric mode | функції немає в старій системі: оберіть іншу функцію (режим версії змінює адміністратор методологій) |

### 19.6. Перевірки середовища (при збереженні й публікації)

Ці перевірки потребують даних вашої системи, тому з'являються після збереження.

| Код | Що означає | Що виправити |
|---|---|---|
| `unknownUnit` | коду одиниці немає в довіднику одиниць | поправте код або додайте одиницю в довіднику |
| `unknownSubstance` | коду речовини немає в довіднику речовин | поправте код речовини |
| `unknownTable` | таблиці немає в жодній чинній версії шаблону | перевірте код таблиці |
| `ambiguousTable` | код таблиці є в кількох шаблонах | напишіть `Шаблон.Таблиця` |
| `unknownColumn` | колонки немає в живій таблиці (або на `Calculated` ніхто не налаштований) | перевірте код колонки; для місячної — чи є хоч один місяць |
| `unknownRegistryEntry` | `entry(…)` вказує на неіснуючий запис довідника | перевірте код довідника й запису |
| `invalidOutputCode` | код виходу недозволений: латиниця, цифри, `_`, перша — літера, до 64 знаків | перейменуйте вихід |
| `noBoundOutput` | жоден вихід не прив'язано до колонки | дайте виходу ім'я колонки `Calculated` таблиці |
| `libraryNotScript` | імпортована методологія не має чинної версії зі скриптом | опублікуйте версію бібліотеки зі скриптом |
| `unitMismatch` | в одному виразі змішано несумісні одиниці | перерахуйте через `CONVERT` |
| `readsOwnOutput` | скрипт читає власний вихід через колонку `Calculated` | приберіть читання власного виходу |
| `resultCycle` | методології читають результати одна одної по колу | розірвіть цикл |

### 19.7. Збереження й публікація (відповіді сервера)

| Повідомлення | Що це | Що робити |
|---|---|---|
| конфлікт збереження (`ECR-CALC-0409`, `scriptChanged`) | поки ви редагували, версію зберіг хтось інший | перезавантажте текст, перенесіть свої зміни, збережіть знову |
| версію не можна редагувати (`scriptNotEditable`) | версія опублікована | створіть нову версію |
| `scriptManaged` | спроба змінити формулу/константу/категорію/вихід такої версії старими екранами | правка лише у скрипті |
| `scriptEmpty` (`ECR-CALC-0422`) | текст порожній: нічого зберігати, публікувати чи показувати | введіть текст |
| текст завеликий (`ECR-CALC-0422`, `scriptTooLarge`) | у тексті понад **1 000 000** знаків: ні збереження, ні перевірка, ні перегляд такого тексту не приймаються. Реальні методології — десятки тисяч знаків | винесіть спільне в бібліотеки, розбийте текст |
| `scriptPreviewRestricted` (`403`) | у вашому профілі обмежений доступ до колонок, а перегляд на документі показує значення входів | попросіть профіль без обмежень або перевіряйте через тести |
| `scriptModuleMissing` (`ECR-CALC-0422`) | у збірці немає модуля розрахунку, що рахує скрипти | зверніться до адміністратора |
| `scriptLibraryUnavailable` (`ECR-CALC-0422`) | бібліотека, яку імпортує скрипт, не має чинної на цей період версії зі скриптом | опублікуйте версію бібліотеки з потрібною датою чинності |
| `scriptResultCycle` (`ECR-CALC-0422`) | методології читають результати одна одної по колу, документ не пораховано | розірвіть цикл (розділ 14) |

## 20. Редактор: від збереження до публікації

> Назви кнопок і вкладок — англійські, як у каталозі інтерфейсу (мова
> інтерфейсу може бути іншою: ключі ті самі).

**Де це.** Configure → Methodologies → методологія → версії → **Open** (для версії з
рушієм Script відкривається редактор скрипта `/admin/methodologies/:id/versions/:vid/script`;
старі секції — формули, константи, виходи, правила — для такої версії не
показуються). Нова версія: **New version** → перемикач рушія **Script** /
**Formulas** (типово Script; при копіюванні з наявної версії рушій береться від
джерела, перемикача немає) → після створення одразу відкривається редактор із
заготовкою з коментованим прикладом. Право редагувати — `Calculation.EditFormula`,
публікувати — `Calculation.Publish`.

**Шапка.** Назва методології й номер версії, код методології, рушій, статус
версії (Draft / Published / Deprecated). Кнопки: **Save** (`Ctrl+S`), **Publish**,
**Compare with version…**, **Edit constant as table**. Опублікована чи застаріла
версія відкривається **лише на читання**: над редактором жовте повідомлення
«Read only», кнопок **Save**, **Publish** і **Edit constant as table** немає,
текст не редагується; вкладки справа працюють (перегляд рахує збережений текст).
Щоб змінити опубліковане — створіть нову версію («New version», копія цієї).
**Compare with version…** недоступна, доки в методології лише одна версія.

1. **Пишіть.** Зліва — текст. Після `row.` підказка пропонує колонки таблиць з
   `rows from` (з чинної версії шаблону); також підказуються ключові слова,
   імена `const/var/function`, вбудовані функції й поля шапки (`header.`).
   Для місячних колонок підказка одразу ставить `Колонка[period.Month]`.
   Помилки підкреслюються за півсекунди після того, як ви перестали друкувати;
   під редактором — рядок стану («Checking…», «No problems found.» або
   кількість проблем).
2. **Проблеми.** Вкладка **Problems** перелічує всі діагностики (з числом на
   вкладці); клік переходить до рядка й колонки.
3. **Збереження (`Ctrl+S` або Save).** Текст зберігається **завжди**, навіть із
   помилками (щоб ви не втратили роботу). Виходи, речовини й імпорти
   записуються в систему лише коли помилок немає. Текст довший за 1 000 000 знаків
   не зберігається (розділ 19.7). Якщо версію тим часом змінив хтось інший —
   другий редактор **не затре** чужу правку: він отримає конфлікт, над редактором
   з'явиться повідомлення «The script was changed elsewhere» з кнопкою
   **Reload script**, а **Save** і **Publish** недоступні. Ваш набраний текст
   лишається в редакторі, доки не натиснете **Reload script**: тоді з'явиться
   збережений чужий текст, і свої зміни треба внести знову (розділ 19.7).
   Позначка «Unsaved changes» стоїть, доки є незбережене; при виході зі сторінки
   з незбереженим текст зберігається автоматично; якщо не вийшло (конфлікт, відмова) —
   питання «Your changes are not saved» («Stay on this page» / «Leave without saving»). Редагувати можна лише **чернетку**.
4. **Живий перегляд.** Справа, вкладка **Preview**: оберіть **Document** (список
   звужується за шаблоном, якщо скрипт називає його), **Period** і, за потреби, окрему
   таблицю → **Calculate**. Рахується текст **у редакторі** — збережений чи ні.
   Таблиця покаже кожен рядок: `Selected` (рахується), `Inactive` (неактивний за
   `active when`), `Not selected` (не підійшов під `where`), `Rejected` (відхилений) —
   і значення всіх `output` (колонками); решту значень рядка видно, якщо його
   розгорнути. Проблеми рядка — «Missing inputs», «Calculation error», «Rejected by the
   script». Нічого не записується: це лише репетиція. Рядків — до 200 (типово 50).
   Якщо в тексті є помилки, замість таблиці показано їх перелік.
5. **Тест із рядка.** У розгорнутому рядку перегляду — кнопка **Create test from this
   row**: відкривається форма тесту (вкладка **Tests**): код (`TEST_1`…), період,
   таблиця «field → value» для входів, таблиця «output → expected value» для
   очікувань (з речовиною, якщо вихід по речовинах) і допуск. Перевірте очікування —
   це ви кажете системі, що число правильне. **Save** записує тест; **Add test**
   створює порожній; **Edit** змінює наявний. Кнопка **Run the golden set** показує
   зелений (Green) чи червоний (Red) вердикт кожного тесту; вона з'являється,
   коли відомий період — оберіть його на вкладці **Preview**. Жодного JSON і
   жодних Id.
6. **Таблиця коефіцієнтів.** Курсор усередині `const`-мапи `{ … }` →
   **Edit constant as table** (якщо курсор не в мапі — підказка «Place the cursor
   inside a constant map { … } to edit it as a table.»). Відкривається вікно
   «Edit constant … as a table»: сітка (рядки — ключі першого рівня, колонки —
   другого; прапорець **Single column (one-level map)** — для мапи в один
   рівень), кнопки **Add row**, **Add column** і хрестики видалення.
   **Вставка з Excel:** або вставте діапазон (`Ctrl+V`) прямо в клітинку, або
   вставте в поле «Paste a table from Excel», за потреби зніміть чи залиште
   галочку **First row holds column names** і натисніть **Replace table with
   pasted data**. Десяткова кома приймається (`1,5` стане `1.5`).
   - Число пишеться в клітинці так, як ви його ввели: `1.0` лишиться `1.0`, а
     не стане `1`; довгі числа не округлюються.
   - Текст у клітинці (напр. `abc`) стає **текстовим** значенням, не помилкою.
     Щоб число збереглося текстом, візьміть його в лапки: `"007"`.
   - **Неоднозначне число** (`1,234.56`, `1.234,56`, `1,234,567`) — помилка
     клітинки: невідомо, чи кома — тисячі, чи десяткова. Напишіть без
     роздільника тисяч (`1234.56`) або в лапках, як текст. Доки така клітинка є,
     **Apply** недоступна.
   - Порожній чи повторений ключ — теж помилка, **Apply** недоступна.
   - **Коментарі зберігаються.** Коментарі над записом і в кінці його рядка
     лишаються на місці, а запис, якого ви не торкались, повертається в текст
     буква в букву. Лише якщо ви змінили чи видалили запис разом із його
     коментарем, коментар зникає, і вікно **попереджає про це наперед**: «Apply
     will remove N comment(s)…». Хочете зберегти — натисніть **Cancel** і
     перенесіть коментар у текст вручну.
   - Якщо мапа такої форми, яку сітка не підтримує (не мапа, значення
     змішані з вкладеними мапами, вкладеність глибше двох рівнів, дубль ключа,
     синтаксична помилка), вікно пояснює причину, а правити треба текстом.
   **Apply** замінює мапу в тексті; відступи й вирівнювання робить сам редактор
   (сервер для цього не потрібен). **Cancel** не змінює нічого.
7. **Порівняння.** **Compare with version…**: оберіть іншу версію методології —
   побачите різницю її тексту й вашого (тут і незбереженого).
8. **Входи й виходи.** Вкладка **Inputs & outputs**: що скрипт читає, що пише, які
   виходи ще **без колонки** («no column» — публікація такого відхилить; прив'язка
   створюється автоматично при публікації за збігом коду виходу з колонкою
   `Calculated`).
9. **Обов'язкові колонки.** Вкладка **Required columns** — той самий екран, що й
   для формул.
10. **Публікація.** **Publish**: вкажіть причину зміни й дату чинності. Кнопка
    недоступна, доки є незбережені зміни (на ній підказка «Save the script before
    publishing.») або є конфлікт збереження. Публікувати може той самий
    користувач, що писав версію, — другий користувач не потрібен, але потрібне
    право `Calculation.Publish`. Система перевіряє: помилки компіляції,
    перевірки середовища (одиниці, таблиці, колонки, речовини, довідники), що
    жоден вихід не залишився без колонки, що є зелені тести (еталонний набір), і
    показує різницю результатів. Перехід методології з `Legacy` на `Strict`
    вмикають лише з нової дати чинності, не заднім числом по вже порахованому. Після публікації документи перераховуються,
    значення з'являються в колонках.

## 21. Як старі налаштування відповідають скрипту

| Було (старий конфігуратор) | Тепер у скрипті |
|---|---|
| Формули (`MethodologyFormula`), порядок обчислення | `var`, `output`; порядок — рядки згори вниз |
| Константи, у тому числі з вікнами дат | `const`; нове значення з нової дати — нова версія (історичні вікна переносить інструмент перенесення в умову за `period.EndKey`) |
| Таблиці коефіцієнтів | `const` із мапою; редактор-сітка |
| Категорії, правило категорії | `reject when …` (відхилити рядок); `if/else` та `?:` (вибір гілки) |
| Правила вибору рядків | `rows from … where …` |
| Фільтр активності | `rows from … active when …` |
| Виходи (`MethodologyOutput`) | `output Код : одиниця = …;` |
| Речовини | `foreach substance S in ("код", …)` і `output … per S` |
| Імпорти (бібліотеки) | `import Код;` і `Код.Ім'я` |
| Прив'язки вихід → колонка | автоматично за збігом коду виходу з колонкою `Calculated`; наявні прив'язки не змінюються |
| Колонки-містки «за місяцем» | `row.X[period.Month]` |
| Режим чисел, календар, трасування | властивості версії (не в тексті) |
| Тести, обов'язкові колонки | без змін (окремі вкладки) |

[visible] var ім'я [: одиниця] = вираз;

reject when вираз;
skip when вираз;                                         // лише в foreach substance
if (умова) { … } else { … }
foreach substance S in ("0301", "0304") { … }
foreach X in (1, 2, 3) { … {X} … }
row.Кол     row.Кол?     key(row.Кол)     row.Кол[місяць]
Таблиця.Кол    (лише в Sum/Min/Max/Avg/First/Count/Any)
