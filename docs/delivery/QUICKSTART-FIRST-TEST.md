# ECR: перше тестування — від нуля до входу

Цей файл лежить у корені набору `ECR-first-test-<версія>.zip`. Набір самодостатній:
на сервері **не потрібні** клон репозиторію, .NET SDK, `dotnet-ef`, Node. Повні
інструкції — `docs/install-guide.md` і `docs/TESTER-HANDOVER.md`; тут мінімум, щоб
дійти до першого входу.

## Що в наборі

| Файл | Навіщо |
|---|---|
| `Ecr.msi`, `Ecr.msi.sha256` | застосунок (служби `EcrApi`, `EcrWorker`) і еталонний хеш |
| `deploy-ecr.ps1` | один виклик: база → схема → MSI → секрети → старт → `/health` |
| `migration.sql`, `sql\*.sql` | схема бази; лежать **поруч** із `deploy-ecr.ps1`, тому він бере їх звідси і `dotnet ef` не кличе |
| `verify-msi.ps1` | перевірка хешу й підпису MSI до встановлення |
| `docs\` | install-guide, TESTER-HANDOVER, TESTER-GUIDE, сценарії, адмін-доки, реліз-нотатки |
| `BUNDLE-INFO.txt` | версія, коміт, хеш MSI, остання міграція — **вказуйте у кожній заявці** |
| `SHA256SUMS.txt` | суми всіх файлів набору |

## 0. Передумови (один раз)

- Windows Server x64 (2019/2022), PowerShell 5.1, права адміністратора.
- SQL Server 2016 SP1+ **Standard/Enterprise/Developer** (Express — лише з `-AllowExpress`,
  без SQL Agent). Обліковий запис, яким запускаєте скрипт, має право `CREATE DATABASE`.
- `sqlcmd` у `PATH` (`sqlcmd -?` відповідає).
- Вільно **≥ 16 ГБ** на диску даних SQL Server (файлові групи; Express — 1 ГБ). `deploy-ecr.ps1`
  вільне місце **не перевіряє**: за браку місця схема падає з `Msg 5149` (код ОС 112) — перевірте
  наперед (`Get-PSDrive`).
- У документах набору шляхи `tools\deploy-ecr.ps1` і `tools\verify-msi.ps1` означають
  `.\deploy-ecr.ps1` і `.\verify-msi.ps1` у корені цього набору (каталогу `tools\` в наборі
  немає; інших скриптів `tools\` тестувальнику не потрібно).
- Сертифікат із закритим ключем у `Cert:\LocalMachine\My` — один і для HTTPS, і для
  Data Protection (`D-267`). Без нього служба в Production **не стартує**. Для стенда
  годиться самопідписаний (крок 3).

## 1. Розпакувати й перевірити

```powershell
Expand-Archive .\ECR-first-test-<версія>.zip -DestinationPath C:\ECR-install
cd C:\ECR-install\ECR-first-test-<версія>
Get-ChildItem -Recurse | Unblock-File          # zip із браузера/пошти позначено «з інтернету»
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

# хеш zip — проти ECR-first-test-<версія>.zip.sha256, отриманого разом із набором
# (виконувати ДО розпакування, у каталозі з zip; обидва рядки мають збігтися з точністю до регістру)
(Get-FileHash .\ECR-first-test-<версія>.zip -Algorithm SHA256).Hash
(Get-Content .\ECR-first-test-<версія>.zip.sha256 -Raw).Trim().Split(' ')[0]
.\verify-msi.ps1 -MsiPath .\Ecr.msi -IntegrityOnly   # [I1] має бути PASS
```

`[I2]` (підпис) поки — `WARN`: MSI не підписано, доки не обрано варіант із
`docs/MSI-SIGNING-OPTIONS.md`. Це очікувано.

## 2. Обліковий запис служби

- **Рекомендовано** — gMSA `DOMAIN\ecr-svc$`: `-ServiceAccount 'DOMAIN\ecr-svc$'`; йому
  потрібні доступ до бази й право читання закритого ключа сертифіката
  (`certlm.msc` → сертифікат → «Усі завдання» → «Керування закритими ключами»).
- **Стенд на одній машині** — без `-ServiceAccount`: служби стають під `LocalSystem`,
  реєструються, але **не стартують самі**: на кроці 7 скрипта (перевірка здоров'я, ~2 хв
  очікування `/health/live`) він завершиться червоним «Служба не відповіла…» — це очікувано,
  не збій (далі — `Start-Service`, розділ 4). Тоді в SQL Server має бути логін комп'ютера/`NT AUTHORITY\SYSTEM` з
  доступом до бази.

## 3. Сертифікат для стенда (якщо замовник ще не видав)

```powershell
$cert = New-SelfSignedCertificate -DnsName 'ecr.test.local', $env:COMPUTERNAME `
    -CertStoreLocation Cert:\LocalMachine\My -KeyAlgorithm RSA -KeyLength 3072 `
    -KeyExportPolicy Exportable -Provider 'Microsoft Software Key Storage Provider' `
    -NotAfter (Get-Date).AddYears(1)
$cert.Thumbprint     # запишіть: він піде і в -DataProtectionThumbprint, і в -HttpsThumbprint
```

Довіра й ім'я (лише для стенда; на майданчику довіра — від ЦС замовника; джерело —
`docs/admin/https-certificate.md` §10.2, де цей сценарій позначено «не виконано» на реальному
стенді — перевіряйте результат):

```powershell
Export-Certificate -Cert $cert -FilePath .\ecr-test.cer | Out-Null
Import-Certificate -FilePath .\ecr-test.cer -CertStoreLocation Cert:\LocalMachine\Root | Out-Null
Add-Content "$env:SystemRoot\System32\drivers\etc\hosts" "127.0.0.1 ecr.test.local"
```

`Import-Certificate` у `Root` і запис у `hosts` потребують прав адміністратора. Це довіряє лише **цій** машині. Для браузера тестувальника на іншій машині імпортуйте `.cer`
у його `Root` і додайте в його `hosts` рядок `<IP сервера> ecr.test.local`.
PFX забекапте окремо від бази: без нього збережені сеанси й ключі не розшифрувати.

## 4. Розгортання

Викликати **у цій самій сесії PowerShell** (`.\deploy-ecr.ps1`, не `powershell -File`):
`SecureString` не переходить у інший процес.

```powershell
$cs = Read-Host -AsSecureString -Prompt 'Рядок підключення'   # напр. Server=SQL01;Database=ECR;Integrated Security=true;TrustServerCertificate=True
$bp = Read-Host -AsSecureString -Prompt 'Разовий пароль bootstrap (запишіть)'

# 4.1 План: нічого не змінює
.\deploy-ecr.ps1 -SqlInstance 'SQL01' -Database ECR -MsiPath .\Ecr.msi `
    -ServiceAccount 'DOMAIN\ecr-svc$' `
    -DataProtectionThumbprint '<відбиток>' -HttpsThumbprint '<той самий відбиток>' -AppPort 443 `
    -WhatIf

# 4.2 Перше розгортання на порожній базі
.\deploy-ecr.ps1 -SqlInstance 'SQL01' -Database ECR -CreateDatabaseIfMissing -MsiPath .\Ecr.msi `
    -ServiceAccount 'DOMAIN\ecr-svc$' -ConnectionString $cs -BootstrapPassword $bp `
    -DataProtectionThumbprint '<відбиток>' -HttpsThumbprint '<той самий відбиток>' -AppPort 443 `
    -FirstDeployment
```

У виводі кроку 2 має бути «migration.sql уже в пакеті — dotnet ef не викликається».
Якщо скрипт просить .NET SDK — `sql\` або `migration.sql` не поруч зі скриптом
(розпаковано не повністю).

Варіанти:
- без сертифіката HTTPS, лише стенд: замість `-HttpsThumbprint … -AppPort 443` —
  `-AllowHttp` (порт 5000; `/health/ready` буде `Degraded` через `transport` — так і має бути);
- без `-ServiceAccount` (розділ 2): скрипт на кроці 7 (~2 хв) завершиться червоним «Служба не
  відповіла…» — очікувано. Далі вручну:
  ```powershell
  Start-Service EcrApi, EcrWorker
  Invoke-RestMethod https://ecr.test.local/health/ready   # або http://localhost:5000/health/ready з -AllowHttp
  ```

## 5. Перевірка й перший вхід

```powershell
Get-Service EcrApi, EcrWorker                                # обидві Running
Invoke-RestMethod https://ecr.test.local/health/ready        # status: Healthy або Degraded з причиною
```

1. Відкрити `https://<ім'я з сертифіката>/` (або `http://<сервер>:5000/` з `-AllowHttp`)
   з **іншої** машини, ніж сервер.
2. Логін `bootstrap`, пароль — з `-BootstrapPassword`. Система одразу вимагає новий:
   ≥ 12 символів, без імені користувача, не з переліку поширених.
3. `/admin/security`: завести собі адміністратора, автора даних (`DataEntry`) і
   погоджувача (`Approver`), видати ресурсний грант на проєкт. `bootstrap` вимкнеться
   сам, щойно інший користувач отримає `Security.ManageUsers` — заведіть свого
   адміністратора **до** цього.
4. Порожня база не має шаблонів і проєктів: далі сценарії В-1 → В-2 → В-3 → Г-1
   (`docs/TESTER-HANDOVER.md` §3.5, §4).

Застрягли — `docs/TESTER-HANDOVER.md` §9 (FAQ) і `docs/install-guide.md` §7–8
(журнали `%ProgramData%\ECR\logs`, журнал подій `Application`, джерело `ECR`).

## 6. Відомі обмеження першого тестування (не дефекти)

Повний перелік — `docs/TESTER-HANDOVER.md` §5 і `docs/release-notes/` (першим читайте `rc-2026-10-30.md`, RC11; далі `rc-2026-10-29.md`, RC10; `rc-2026-10-28.md`, RC9; `rc-2026-10-27.md`, RC8, `rc7-ui.md`, UI-частина RC7, `rc-2026-10-26.md`, RC7, `rc-2026-10-25.md`, RC6, `rc-2026-10-24.md`, RC5, і `rc-2026-10-23.md`, RC4). Найважливіше:

1. **PI на стенді немає**: джерела PI відключені або порожні; сценарії збору з PI
   (И-2…И-5, И-9, И-10) пропускаються (`TESTER-HANDOVER` §4.2).
2. **MSI не підписано** (`[I2]` — WARN), цілісність — лише SHA-256.
3. **SMTP типово не налаштовано**: листи лишаються `Pending`/`Failed` без повтору.
4. **ru/kz — машинний переклад**; `login.title` у ru/kz англійською (свідомо).
5. **Звірки з чинною системою, пілоту RDL і замірів на залізі замовника не було.**
6. **Оновлення стирає `Environment` служб**: після кожного `msiexec` повторіть
   `deploy-ecr.ps1` (без `-BootstrapPassword` і `-FirstDeployment`).
7. **Втрачено пароль `bootstrap`** — відновлення лише новою порожньою базою
   (`TESTER-HANDOVER` §3.7); дані старої не переносяться.
8. Дрібне, відоме: подання аркуша зі застарілою версією визначення дає `404` замість
   `409`.
9. Швидкий набір у сітці (T3-01/T4-01; стрілка ↑↓←→ після набору зберігає значення й
   переходить, як в Excel — A1-03): інтервали 10–120 мс, стрілки (A/B/C/D), Ctrl+V/C після
   стрілки й F2 — стабільні. Серії з інтервалом 0 мс між клавішами на повільних/завантажених
   машинах нестабільні: у живому прогоні 7 з 20 (перше значення на повторному проході
   губиться). Довгі вирази: ланцюг >1024 операторів відхиляється з 422 `ECR-TMPL-0422`
   (`expr.chainTooLong`); формули методології (PUT .../formulas/{code}) такий ланцюг не
   відхиляють (200); формула, збережена до оновлення й глибша за 96 рівнів, при перерахунку
   мовчки пропускається; `POST /expressions/validate` для Template/Report тепер також відхиляє вираз 2001–4000 (422 `ECR-REQ-0422`, RC6).
   Правка тексту всередині поля — Enter, F2 або
   клік. Backspace/←/Home у перші мс після відкриття редактора нічого не роблять
   («1, Backspace, 2» за 0 мс дає «12»). Ctrl+C у вікні переходу через `navigator.clipboard`:
   без HTTPS і в Safari мовчки не копіює.
10. Відомі пункти приймальної №2–№3 і RC4, що лишились (перший документ реліз-нотаток — `docs/release-notes/rc-2026-10-23.md`; `rc-2026-10-22.md` — другий, RC3; `rc-2026-10-20.md` — третій, історичний):
    - Екран примусової зміни пароля не має перемикача мови (`D-292`, свідомий компроміс; 428 на `/languages` закрито).
    - Значення Date у **тілах** таблиць експорту CSV/JSON має вигляд `2026-10-06T00:00:00` (з нульовим часом); у шапці — `yyyy-MM-dd`.
    - A1-05: користувач `bootstrap` без ролі TemplateAdministrator не видає гранти на колонки (403 `/templates`); обхід — користувач з ролями BootstrapAdministrator і TemplateAdministrator (задум).
    - Один запит `/public/bootstrap` на сторінці входу може дати 428 у консолі (не впливає на вхід).
    - A2-03 (задум, інформація; політика D-230/D-250): невідомі поля зв'язку (напр. `by`) ігноруються; Check без `keys` порівнює рядок джерела з приймачем лише коли в приймачі один рядок. Панель валідації тепер показує про це інформаційну підказку (Info). Див. «Row matching» у `docs/admin/admin-guide.md`.
    - Шапка в xlsx-експорті: довгі значення обрізаються на 50 символах ширини колонки.
    - `/me` віддає лише глобальні права ролей: для ролі з областю проєкту кнопка «Submit» може бути сірою, хоча сервер подання дозволить.
11. Що нового в RC6 (перевіряйте, це не обмеження; деталі — `rc-2026-10-25.md`; RC6 не містить UI-змін, UI-пачка — RC7):
    - Безпека схованих аркушів: «хто/коли правив» і `hasLateEdits` (R-7) не розкривають схований аркуш; роль зі звуженням за кодами аркушів не бачить зведених лічильників кампанії/прогресу по всьому документу (R-8; ⚠ зміна поведінки для користувача з кількома ролями — лічильники `null`).
    - Тексти помилок PI-збору, SQL-джерел, перерахунку, доставки листів, `/health/ready` і розкладів збору — загальні, англійською; деталі — у журналі сервера за `correlationId`/`runId`. Старі записи в БД можуть містити сирий текст.
    - `POST /expressions/validate` відхиляє вираз 2001–4000 символів (Template/Report) — 422 `ECR-REQ-0422`.
    - Нові серверні поля й маршрути для майбутнього UI (клієнт їх поки не показує). Міграцій немає; сід: додано один ключ повідомлення, змінено текст одного наявного (довжина виразу), правки адміністратора зберігаються.
    - Відомо (не дефект): у шаблоні документа для автора з Deny на аркуш видно код і назву схованого аркуша (R-6); `/audit/cells` без `documentId` для `Security.ViewAudit` бачить усе (Q-177); булеві канали «існує подане» (D-299).
12. Що виправлено в RC5 (перевіряйте, це не обмеження; деталі — `rc-2026-10-24.md`):
    - Довгі плоскі формули (до 1024 доданків) тепер рахуються. ⚠ Зміна поведінки: після оновлення в комірках з'являться значення там, де раніше був `#BUDGET` або порожньо.
    - Глибина вкладення > 96 відхиляється при збереженні/публікації (422 `ECR-EXPR-0422`, `expr.tooDeep`); у правилах валідації в експлуатації — Warning `validation.rule.budget`.
    - Текст у клітинці довший за 1000 символів — людська відмова (`validation.column.maxLength`); в імпорті xlsx — відхилення у перегляді, а не відмова всієї книги на Apply.
    - Вираз довший за колонку (2000; правила довідника — 4000) — 422 `ECR-REQ-0422` замість 500.
    - Безпека: приховані від читача аркуші не розкриваються в переліку/картці документів, фільтрі стану, відмовах дій (404 замість 403), 409 і результатах розрахунків; тексти помилок фонових задач загальні (деталі - в журналі сервера за correlationId). Для звуженого читача `errorCount`/`warningCount` у списку - «—».
    - A4-01: мова з екрана входу завжди переноситься в сесію. A4-02: Enter у `PeriodPicker` на повному періоді закриває поле й показує назву. Сторінки 403/404: заголовок без рамки фокуса в один рядок.

    Що виправлено в RC4 (перевіряйте, це не обмеження):
    - A3-01: недійсна дата в полі шапки (`31.02.2026`) після Enter або Escape показує відмову під полем (раніше лише на blur).
    - A3-02: список документів відкривається з найновішим відкритим періодом серед календарів проєктів; межа — 10 проєктів (більше — період обирає людина); лише при вході без періоду, не після очищення поля.
    - A3-03: скасований клієнтом запит `/csp-report` не лишає запису Error («Необроблений виняток») в журналі.
    - Період із назвою місяця: у фокусі поле показує `YYYYMM` для набору, на blur — назву місяця мовою інтерфейсу (en/ru/kz).
13. **Згортання меню.** Кнопка-шеврон у **нижній** частині бічної навігації, під пунктами (лише при ширині вікна від `sm`; на екрані примусової зміни пароля меню немає). У РОЗГОРНУТОМУ меню кнопка має видимий підпис: en «Collapse menu», ru «Свернуть меню», kz «Мәзірді жию». У ЗГОРНУТОМУ меню від кнопки лишається лише іконка (шеврон «вперед»), а підпис стає підказкою при наведенні та доступною назвою: en «Expand menu», ru «Развернуть меню», kz «Мәзірді жаю». Меню звужується до іконок (назва пункту — у підказці). Стан запам'ятовується на сервері (налаштування `navbarCollapsed`) і локально та відновлюється після F5 і на іншому пристрої.
14. **Стрілки в сітці.** У редакторі, відкритому Enter, F2 або кліком, стрілки рухають курсор у тексті. Після набору без редактора (значення набрано одразу) стрілка зберігає значення й переходить до сусідньої клітинки.

## 7. Дефект

GitHub Issues у `BabychPV/ECR` (шаблон «defect»). У заявці: `version` і `commit` з
`BUNDLE-INFO.txt`, роль, кроки, очікуване/фактичне, `X-Correlation-Id` з відповіді
або журналу. Пріоритети й строки — `docs/TESTER-HANDOVER.md` §6.
