Пачка переводить екрани застосунку на гібридний макет `docs/design/hybrid` (KIT.md). Джерело змін — лінія `lane/cloud/batch-5-rc7`: batch-4 (разом з batch-2-a і batch-3b), mockup-polish-b4, mockup-polish-b4b, a11y-batch4 і окремий docs-коміт з інструкціями користувача. Серверні адитивні поля й маршрути для екранів описані в `rc-2026-10-25.md` (RC6); у цій пачці клієнт їх уже споживає.

## Зміни, що зачіпають безпеку

`UI-31 / P1`: майстер створення документа більше не показує аркуші, яких користувач не бачить (`Deny` на аркуш). Правило те саме, що для читання документа (`DocumentReadScope.CanReadSheet`).

## UI відповідає макету: частково

За макетом: оболонка, меню, палітра, дошка, інспектор документа, Security, перелік шаблонів, шаблон переліку на Units / Registries / Consistency / Jobs, 403 / 404, картка шаблону, шапка конструктора, «← Back to Documents» і смуга аркушів, 500 px без горизонтальної прокрутки.

Розбіжності з макетом, що лишаються (джерело — `MOCKUP-CHECK-batch-4`, мінус виправлене в b4 і b4b):

1. Сторінка входу: «Sign in with Windows» не головна кнопка; локальна форма відкрита одразу, а макет ховає її за «Use a local account». Свідомо не змінено: e2e-набір входить через локальну форму.
2. Документи: лічильники станів у рядку фільтрів замість StatStrip; набір фільтрів не за макетом.
3. Документ: «History» і «Compare versions» окремими рядками (у макеті вкладки).
4. Картка шаблону: опис зміни, автор версії й вкладка Usage не показані (контракт не віддає, D15-06); немає «Open / Continue» на кожній версії. 403: ролі, що мають право, не показані (клієнт без `Security.View` їх не знає).
5. Units: розмірність показується кодом (людської назви контракт не дає).
6. P3: підписи над полями фільтрів, KeyValue підписами над значеннями в шторках, кнопки футера шторок, плитки Periods 6×2, StatStrip в Audit trail, меню типово розгорнуте з підписами.
