# Release note: NAE — район вузла, необов'язковий SITE (AN-158)

## Що виправлено
- **Район «_____» у джерела НАЕ.** Ручний REGION/AREA-вузол не зберігав власного коду (`RegionCode`/`AreaCode`), а похідний код брався з технічного, де кожна не-ASCII літера ставала `_` — район, введений кирилицею, перетворювався на `_____`. Тепер вузли REGION/AREA зберігають власний код при створенні (ручний корінь, Excel, AF), похідний код із самих `_` вважається порожнім, а технічний код не-ASCII частини містить 8-hex хеш (`A_ATYRAU_3F2A91C0`), а не підкреслення.
- **Район вибирається зі списку** «Air permit areas» (діалог «Додати регіон» і поле «Район» вузла AREA); вільний текст відхиляється (`422 naeAreaNotInList`).
- **SITE необов'язковий:** групу обладнання й джерело можна створити прямо під районом (або регіоном). Імпорт з AF/Excel приймає коротший ланцюг. На старті наявні дерева отримують `SITE` як необов'язковий рівень (аудит `NaeSiteOptional`).
- **UI:** рядок «AF path» прибрано з картки вузла; на сторінці структури одна панель кнопок (Add region · Import from Excel… · Load from PI AF); «Add top-level node» прибрано.

## Наявні дані (перевірка при оновленні)
На старті (ідемпотентно, аудит `RepairScopeCodes`): вузли REGION/AREA без власного коду, чий похідний код осмислений (ASCII), отримують його збереженим. Вузол, чий код розплющено в `_____`, лишається з ПОРОЖНІМ районом — оригінальний текст втрачено, його не вигадують.

**Як виправити існуючий вузол AREA з порожнім районом:** відкрити вузол AREA → у полі «Район» вибрати значення зі списку → зберегти; коди джерел під ним оновляться автоматично (каскад 03.11).

Міграції немає (лише дані); контракт не змінено.
**Контракт:** код імпорту Excel `siteRequired` більше не повертається (SITE необов'язковий); знімок OpenAPI і `schema.d.ts` оновлено, клієнтська мітка `siteRequired` лишилась нешкідливою.
