- `CellAccessContext.CellIsComputed`: `EditRules.CanEdit` -> `CalculatedCell` (`ECR-CELL-4221` на PATCH) — після закритого періоду/поданого аркуша; «стерти значення» ознаку не враховує (як і ознаки колонки).

- Ворота `ECR-TMPL-4227` — лише для `Scope=Column`; Cell/Row не вимагають обчислюваної колонки.
- Замість readOnly-рядків (які блокували б ~755 комірок вводу): 0 рядків `readOnly`.

## Відомі обмеження

- `Build -StructureMode Sql`: масова вставка формул комірок не проганялась на БД (перший живий прогін).
- ~6,7 тис. комірок/документ-період писатимуться як 0 (паритет Excel); розмір таблиці значень і каскад Waste (елемент -> `8001002` -> Input/Output -> Balance -> наступний місяць) не вимірювали.
- `migrate-version` проєкту з даними: у живих документах у комірках групових підсумків можуть бути збережені значення прода -> Guarded/`guardedWithData`. Рішення продукту: «перезаписати похідні підсумки при міграції» чи ні; цифри `lostValues` на копії дасть Аналіз.
- Debt: Remarks у `TemplateVersionsController.SaveCellFormula` («Колонка комірки мусить бути обчислюваною (4227)») застарів і потрапляє в `openapi.snapshot.json`; перегенерація контракту — окремо.
- Debt: `GetTableStatus` рахує комірки з Cell-формулою вхідними (знаменник «заповнено X з Y» трохи завищений).
- Успадковані обмеження RC23–RC36 — у `rc-2026-11-14.md` … `rc-2026-11-27.md`.
