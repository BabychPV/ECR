## Що це за система

> **Універсальний інструмент побудови та заповнення структурованої звітності.**
>
> Проєкт на рік -> версійний шаблон (аркуші, таблиці, стилістика) -> згенеровані
> з нього документи з обраним набором аркушів і таблиць -> заповнення -> валідація
> -> затвердження.

ECR (екологічна звітність) — **перший сценарій застосування**, а не сама система.
Ядро не знає ні про екологію, ні про PI AF.

```
┌──────────────────────────────────────────────────────────────┐
│  ЯДРО (домен-агностичне)                                     │
│  Проєкти · Версійні шаблони · Стилі · Зв'язки таблиць        │
│  Генерація документів · Формули · Валідація · Workflow       │
│  RBAC · Аудит · Excel export/import                          │
└───────────────────────────┬──────────────────────────────────┘
                            │ підключувані адаптери
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
   PI AF Connector    Розрахункові        Майбутні джерела
   (джерело даних)    модулі емісій       і споживачі
                      (перша черга, D-54)
```

## Ключові рішення

### 1. Дані — сутність з іменованими полями, а не рядок

**Зараз:** весь рядок таблиці пишеться в один текстовий атрибут PI AF:

```
Attribute_0010 = "1;7001001;ITEM;094f83a4-…;0151202a-…;;125.5;1;0;0;0;"
```

Що означає сьоме значення — знає тільки код VBA. Ідентичність рядка **позиційна**,
тому вставка рядка в Excel зсуває нумерацію і старі дані починають означати інше.

**Стане:**

| Рівень | Ідентичність |
|--------|--------------|
| Таблиця | `TableDef.Code` |
| **Рядок** | **`RowKey`** — стабільний бізнес-ключ (`7001001`), не позиція |
| **Поле** | `ColumnDef.Code` + `DataType` |
| Значення | типізоване: `Numeric` / `String` / `Date` / `Bool` / `Lookup` (з FK на довідник) |

Порядок відображення (`Ordinal`) відокремлений від ідентичності (`RowKey`).

### 2. Структура — це дані, а не код

Усе, що зараз є VBA і координатами комірок (`Configuration.bas`, `Sheet_Config.bas`,
Excel Data Validation, номери рядків у `Protection.bas`, стилі), стає записами в `cfg.*`.

**Фізична схема БД ніколи не змінюється.** Додати колонку = `INSERT`, не `ALTER TABLE`.

### 3. Опубліковані версії шаблону структурно незмінні

```
v1.0 [Published] ← документи 2025    v1.1 [Published] ← документи 2026
                                     v1.2 [Draft]     ← редагується
```

Нова версія = `CloneFrom` попередньої. Документ назавжди прив'язаний до своєї версії
і мігрує на нову **тільки явною операцією** з dry-run і повним відкатом.

Опублікована версія має **два шари**: структурний (типи, ключі, формули,
`Error`-правила) — заморожений; **презентаційний** (підписи, переклади, стилі,
порядок, `Warning`-правила) — патчиться «на льоту» без нової версії, з аудитом.

Зміни класифікуються: 🔵 `Presentation` (навіть у Published) / 🟢 `Safe` (у Draft) /
🟡 `Guarded` (потрібна стратегія + звіт про вплив) / 🔴 `Breaking` (заборонено
у версії з документами).

### 4. Зв'язування таблиць — опційний механізм

Шаблон ECR має аркуш `2. Contract` як метадані для всіх таблиць.
Інші шаблони можуть не мати зв'язків узагалі.

6 типів: `MetadataSource` · `Lookup` · `Rollup` · `Mirror` · `ParentChild` · `Constraint`.

Замінює зашиті у VBA `GetContractSheetAttributes`, `modB16AmendmentFlow` (764 рядки),
автовиклик `SaveWaterConsolidationForMonth`, `ExpandLinkedSheetGroups`.

### 5. PI AF — джерело даних, не сховище; два транспорти

Система обліку — **SQL**. PI AF залишається джерелом сирих даних і довідників,
які існують тільки там. Зібране зберігається напряму в SQL (схема `ext`),
без інтерпретації.

Адаптер має **дві реалізації за одним інтерфейсом** `IPiAfDataReader`:

| Транспорт | Для чого |
|-----------|----------|
| **PI Web API** | метадані, довідники, `SETTINGS`, точкові операції, *(опційно)* запис |
| **PI SQL Client** | масове читання з фільтрацією **на боці PI** — міграція історії, регулярний збір |

> Зараз система вивантажує 1000 Event Frames і фільтрує їх у VBA-циклі, бо
> Web API не вміє фільтрувати за значенням атрибута. PI SQL Client робить
> те саме одним `WHERE`.

### 5a. Архівування закритих років

Підхід із чинного рішення зберігається: після завершення року **і** спливу
offset (`YearGraceOffsetDays`) дані переносяться з `doc.*` у `arc.*`
(columnstore, стиснення 5–10×), транзакційно і зі звіркою контрольних сум.

Робочі таблиці тримають обсяг **приблизно одного року**, а не N років —
система не деградує з часом. Читання архіву прозоре; `Reopen` виконує
зворотне перенесення.

### 6. Уся предметна конфігурація — у вебі, не в файлах

Через UI налаштовуються: структура, стилі, формули, правила валідації,
**зв'язки між таблицями** (візуальний граф + майстер), правила складу документа,
довідники, політики періодів, **ролі і права**, політика паролів,
мапінг зовнішніх джерел.

> У конфігураційних файлах залишаються тільки рядки підключення і технічні
> параметри інфраструктури.

### 7. Автентифікація — два провайдери, авторизація — одна

```
Windows (Negotiate/Kerberos)  ─┐
                               ├─►  єдина ідентичність застосунку  ─►  RBAC
Локальний логін + пароль      ─┘
```

Адміністратор створює локального користувача з паролем, дає ролі — і той працює.
При однакових ролях права доменного і локального користувача **ідентичні**.

⚠ **Наслідок:** локальні користувачі не мають Windows-ідентичності, тому
Kerberos-делегування до PI для них неможливе — сервісний обліковий запис
стає єдиним цілісним варіантом.

### 8. Ролі — дані, а не enum

Адміністратор створює роль і набирає їй два види прав:

| Вид | Приклад |
|-----|---------|
| **Функціональні** | `Template.Publish`, `Period.Reopen`, `Document.Approve` |
| **Ресурсні** | `Sheet "7. Water Report" → Write`, `Sheet "9. Utility" → Read`, `Column "Cost" → None` |

Рівні: `None` -> **`Read`** -> `Write` -> `Submit` -> `Approve` -> `Manage`.
Успадкування `Project -> Sheet -> Table -> Column`, найконкретніший грант виграє,
явна заборона (`IsDeny`) виграє завжди.

«Тільки читання» — трьома способами: роль із грантами `Read`, прапорець
`IsReadOnly` на призначенні, або системний стан (закритий період, `Approved`-документ).

### 9. Довідники — один механізм для всього

Плоский список (`Generic_EquipStatus`) і складна сутність (`Permit` із правилами,
каскадами і вкладеними речовинами) — **один механізм**, різниця лише в кількості
полів і зв'язків. Адміністратор створює довідник у вебі, як таблицю.

| Зв'язок | Приклад із ECR |
|---------|----------------|
| `Cascade` | `Type -> Indicator`, `Entity -> Location` |
| `Composition` | `Permit -> Pollutant[]` |
| `Association` | `Permit × WaterBody -> Usage` (матриця `Configuration!BD:BL`) |
| `Hierarchy` | `WasteGroup -> WasteItem` |

**У комірці зберігається ID, а не текст.** Зараз пишеться `"Diesel - Дизель"`;
перейменували значення — історичні дані «відв'язалися». Стане `ValueRegistryEntryId`
+ `DisplayTemplate` — зв'язок цілий, назва оновлюється скрізь.

**Версійність на двох рівнях:** структура довідника (як `TemplateVersion`)
і записи (`SoftDelete` / `Temporal` з `ValidFrom`/`ValidTo` / `Full`).
Запис ніколи не видаляється фізично, якщо на нього посилаються дані.

Замінює ≈7 800 рядків VBA: `AddPermitAir/Water`, `AddPollutantEmissionFees`,
3 форми і 5 модулів синхронізації.

### 10. Періоди з налаштовуваними offsets

Замість одного «дня відсічення» — стани `Scheduled -> Open -> Grace -> Closed`
з зсувами, які задає адміністратор:

```
01.09 ──────────── 30.09 ─────────── 15.10 ─────────── 30.10 ────►
  Open                │  Grace (+15)   │                 Closed
                      └────────────────┘
```

* `GraceOffsetDays` — скільки днів після завершення періоду дані ще редагуються;
* `YearGraceOffsetDays` на проєкті — скільки після завершення **року**
  можна правити минулий рік;
* рівні: глобально -> проєкт -> окремий період -> роль (`ExtraGraceDays`);
* зміни у `Grace` позначаються в аудиті прапорцем `IsLateEdit`.

⚠ **Ліцензійні пастки, яких уникаємо** (перевірено — [15](15-verified-stack.md)):
HyperFormula (GPLv3), EPPlus 5+ (non-commercial), Handsontable (платна для
комерційного використання), AG Grid Enterprise (платна).
Перевірку ліцензій закладено в CI: `DENY: GPL-*, AGPL-*, SSPL, Polyform-*`.

ℹ **Hangfire — LGPL.** Використання як NuGet-залежності в закритому застосунку
дозволено; заборонено лише розповсюджувати приватні форки. Потребує підтвердження
ІБ/юристів; альтернатива — Quartz.NET (Apache 2.0).

**Локалізація:** EN / RU / **KZ**.

**Чому EF Core, а не DataObjects.Net (Xtensive):** обидва MIT і активні, але
головна перевага DataObjects.Net — автоматична еволюція схеми при старті
(`DomainUpgradeMode`) — у нашій архітектурі майже не працює: фізична схема
**зафіксована**, зміна шаблону це `INSERT`, а не `ALTER TABLE`. Основна складність
тут — масові операції на 108 млн рядків, партиціонування і columnstore, де
екосистема EF Core багатша. Плюс наймання і супровід на 10+ років.
Детально — [ТЗ §5.4-A](06-tz-architecture.md).

## Оцінка (переглянута — ТЗ §13)

|---|---|

| 1 арх + 3 BE + **2 FE** + 1 QA | **11–13 місяців** |

**Архітектура реалістична; строки початкового roadmap — ні для заявленої команди.**

шари на реальних даних за ~3 місяці, і лише потім generic-конфігуратор і UI.

## Що треба вирішити

15 питань у [ТЗ §12](06-tz-architecture.md#12-рішення-які-треба-прийняти-до-старту)
(і 15 уже прийнятих рішень там само).
Найкритичніші:

1. **Grid-компонент** — за результатом прототипу на Етапі 0
2. **Чи доступний PI SQL Data Access Server** у контурі — впливає на оцінку міграції
3. **Гранулярність затвердження** — документ / аркуш / (аркуш × місяць)
4. **Політика паролів і 2FA** — параметри; чи обов'язкова 2FA і для кого
5. **Чи є SMTP у контурі** — від цього залежить самостійне скидання пароля

*(Питання про делегування до PI фактично закрите: вимога локальних облікових
записів робить Kerberos S4U2Proxy непридатним як цілісну модель — лишається
сервісний обліковий запис. Потребує формального підтвердження ІБ.)*

✅ **Питання про довідники, зворотну публікацію і склад даних з AF закриті
(2026-09-03):** master довідників — ECR, поетапно (D-49); **зворотної публікації
в AF немає взагалі** (D-44); після переходу з AF збираються лише сирі виміри і
FLERT (ER-I-02). Реєстр — [`tz/10-decisions.md`](../../tz/10-decisions.md).
Саме тому `PiAfConnector` спроєктований як **змінний
адаптер**, а не як частина ядра: будь-яке з цих рішень зачепить лише обсяг
робіт по адаптеру, а не архітектуру системи.

Плюс **обов'язковий Етап 0** (3–4 тижні): навантажувальний тест на 108 млн рядків,
прототип grid, тест рушія формул, аудит ліцензій. Без нього не починати Етап 1.
