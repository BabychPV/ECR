## 1. Один застосунок, розділення за правами

Один SPA обслуговує і адміністрування, і роботу користувача (ТЗ §2.2).
Розділення — маршрутами і `AccessProfile`, не окремими застосунками.

```
/                      → залежить від ролі: список документів або дашборд
/documents             робота з даними          ← 70 % користувачів
/config                конфігуратори            ← адміністратори, методологи
/reports               звіти                    ← усі
/admin                 безпека, система         ← адміністратори
/ops                   експлуатація             ← адміністратори, підтримка
```

**Правило видимості (ФВ-5.4, [11] §10 сц. 7):** ресурс із рівнем `None`
**не приходить із API взагалі**. Клієнт нічого не «ховає» — він не знає про те,
чого не має бачити. Меню будується з `AccessProfile`, а не з константи.

## 3. Grid-редактор

**Найважча область і критичний шлях.** Замінює те, заради чого користувачі
тримаються за Excel.

### 3.1 Обов'язкова поведінка (ФВ-3.3)

| Функція | Деталь |
|---------|--------|
| Навігація клавіатурою | Tab / Enter / стрілки / Home-End / Ctrl+стрілки — як в Excel |
| Виділення діапазону | миша, Shift+стрілки, Ctrl+A по таблиці |
| **Вставка з Excel** | Ctrl+V багатоклітинного буфера з правильним розбором роздільників і десяткової коми |
| Копіювання в Excel | Ctrl+C у форматі, який Excel приймає |
| Fill handle | протягування вниз/вправо, подвійний клік по маркеру |
| Undo/Redo | Ctrl+Z / Ctrl+Y, не менш ніж 50 кроків, у межах таблиці |
| Віртуалізація | 500+ рядків × 60 колонок без просідання скролу |
| «Брудні» комірки | візуально відрізняються до збереження |
| **Пізня правка** | банер «період у Grace, лишилось N днів» + модалка «причина правки» перед першим `PATCH` (B04 §5.4, B05 §3) |
| Заблоковані комірки | інший фон + **причина в підказці** (`EditDenyReason`) |
| Помилки валідації | маркер у комірці + повідомлення поруч |
| Обчислені комірки | інший стиль, редагування недоступне |

### 3.2 Взаємодія з бекендом

```
Відкриття:  GET /api/v1/documents/{id}/tables/{code}?period=…&offset=…&limit=500
            (limit: типово 500, max 2000 — B01 §5)
            → { columns[], rows[],
                cells[{ rowKey, columnCode, value, isEmpty, isCalculated }],
                permissions{}, validation[] }
            комірки немає в cells[] → незаповнена (клієнт бере ColumnDef.DefaultValue);
            isEmpty: true → явно порожня, у масиві присутня
              бюджет 1.5 с p95 ([14] §2 п.3)

Правка:     debounce 400 мс → накопичення в чергу змін
            lateEditReason — ОБОВ'ЯЗКОВИЙ, якщо permissions.period.requiresReason = true
            (інакше 422 до транзакції, B04 §5.4)
            PATCH /api/v1/documents/{id}/cells  (батч, ≤ 2000 комірок)
            If-Match: версія TableInstance; baseVersion на кожен рядок
            → 200 { applied, recalculated[], validation[], newVersions{} }
            → 409 { conflicts[] } → діалог розбіжностей
            → 422 { errors[{ rowKey, columnCode, code, message }] } → підсвітити
            → 403 { errorCode, denied[{ rowKey, columnCode, reason }] } → підсвітити
                  і пояснити (reason = EditDenyReason)
            → 401 (SecurityStamp змінився) → зберегти чернетку, перелогінити,
                  повторити батч

Формули:    formulajs локально — миттєва підказка;
            серверне значення з відповіді ЗАВЖДИ замінює локальне;
            розбіжність показується як попередження, не тихо
```

**Три правила, які легко порушити:**

1. **Клієнтське значення формули ніколи не зберігається** (ТЗ §5.2) — воно
   візуальна підказка, і при розбіжності виграє сервер.
2. **`value: null` / `isEmpty: true` / відсутнє поле — три різні операції**
   ([B04](B04-write-path.md) §2.2). UI має розрізняти «стерти», «явно порожньо»
   і «не чіпав».
3. **Права не питаються на комірку** — приходять мапою при відкритті
   ([B05](B05-security-runtime.md) §3).

### 3.3 Ризик

RevoGrid — open-core. Fill handle, range selection і clipboard **треба
підтвердити в MIT-ядрі** на прототипі Етапу 0 ([15] §8 п.1); запасний —
Glide Data Grid, крайній — AG Grid Enterprise.

## 4. Конструктор шаблону

Реалізує ФВ-2.1…2.18. Дерево `Template → Version → Sheet → Table → Column/Row`.

| Екран | Зміст |
|-------|-------|
| Дерево версії | навігація, пошук, ознака `Draft`/`Published`/`Deprecated` |
| Редактор таблиці | колонки (drag-and-drop порядку), типи, формати, довідники, каскади |
| Редактор рядків | `RowKey`, `RowType`, ієрархія, стилі |
| Редактор стилів | іменовані стилі + умовне форматування, живий перегляд |
| Формули | вираз + перевірка + «де використовується» |
| Правила періодів | шість типів `RuleKind` + **матриця `період × аркуш`** (ФВ-2.18) |
| Версії | `CloneFrom`, `Diff(v1,v2)` з класифікацією змін, `Publish` із валідацією |
| **Звіт про вплив** (контракт — [B10](B10-decisions.md) §3.2, поле `impact`; endpoint — [B01](B01-backend-blueprint.md) §5) | перед будь-якою зміною класу `Guarded`: скільки документів і комірок зачепить |

**Ключова взаємодія:** зміна класифікується (`Presentation` / `Safe` /
`Guarded` / `Breaking`) **на сервері**, і UI показує клас **до** застосування.
`Breaking` у версії з документами — відмова з поясненням, не попередження
([10] §3).

## 6. Конфігуратор методологій

Реалізує [B19](B19-calc-configurator.md). Найбільша нова область.

**Режим групи методологій** (`Mirror` / `Hybrid` / `Master`, [B19](B19-calc-configurator.md) §7)
приходить із API разом із деревом. У `Mirror` доступні лише перегляд, тести
і покриття; дії редагування недоступні з поясненням «майстер — PI AF».

### 6.1 Навігація

```
Група (ECW_C05) → Методологія (ECW_C05_01) → Версія (за датою)
   ├─ Формули      список → редактор виразу
   ├─ Константи    список → категорії → значення по вікнах дії
   ├─ Правила      прив'язка до таблиць + покриття
   ├─ Скрипти      Monaco + тести
   └─ Тести        набори входів/очікувань, статус останнього прогону
```

### 6.2 Редактор формули (рівень 1)

* автодоповнення `CST.` (константи), `!` (інші формули), `@` (аргументи рядка) —
  як у чинному PI Vision, але з типом і одиницею в підказці;
* валідація на льоту: оператори, функції з дозволеного набору (24), дужки;
* **перевірка «усі токени виразу є в списку аргументів»** — сьогодні розходження
  мовчазне і формула тихо рахує без пропущеного аргументу;
* попередження про цілочисельне ділення (`365/31 = 11`);
* **«Спробувати»** — підстановка реального рядка джерела і показ результату
  покроково, до збереження;
* «Де використовується»: які правила, таблиці й періоди зачепить зміна.

### 6.3 Редактор скриптів (рівень 2)

* Monaco з C#-підсвіткою, автодоповненням по контексту (`Args`, `Const`,
  `Substances`, `Emit`, `Warn`, `Trace`);
* помилки компілятора **інлайн**, до публікації;
* заборонений API підсвічується як помилка з поясненням, чому саме;
* панель тестів: набори входів, очікування, допуск; **публікація заблокована,
  доки хоч один обов'язковий тест червоний**;
* diff версій коду; `ChangeReason` обов'язковий у діалозі публікації.

### 6.4 Правила прив'язки

| Елемент | Зміст |
|---------|-------|
| Матриця «таблиця × методологія» | які таблиці обслуговує кожна методологія, скільки правил |
| Редактор правила | таблиця → колонки (з **реальними значеннями** з даних) → значення → вікно дії |
| Перевірка перетину | **до збереження**: з якими правилами перетинається і на яких значеннях |
| **Покриття** | по таблиці: % рядків, які матчаться, і список непокритих комбінацій із кількістю |
| Симуляція | обрати рядок → показати, яке правило спрацювало і яка методологія |
| Звіт про вплив | скільки рядків/документів/періодів перерахується |

### 6.5 Версійність — спільний віджет

Використовується в методологіях, звітах, реєстрах, шаблонах:

```
┌ Версії ────────────────────────────────────────────────┐
│ v3  01.01.2026 – …      Published   Іванов  01.12.2025  │
│     «Коефіцієнт за наказом №215 від 20.11.2025»         │
│ v2  01.01.2025 – 31.12.2025  Deprecated                 │
│ v1  01.01.2024 – 31.12.2024  Deprecated                 │
└─────────────────────────────────────────────────────────┘
[Нова версія]  [Порівняти]  [Переглянути на дату: ____]
```

`ChangeReason` — обов'язкове поле діалогу публікації; порожнє не проходить.

## 7. Конвеєр

Редактор декларативного конвеєра ([B22](B22-nocode-and-realism.md) §2):
послідовність кроків (`source` → `join` → `filter` → `group` → `compute` →

## 7а. Звіти

Конструктор ([B16](B16-ecr-reporting.md) §2): параметри, колонки, джерела,
правила (`Value` / `Aggregate` / `Lookup` / `Window` / `Script`);
попередній перегляд зрізу; кнопка «Побудувати зріз»; історія зрізів із
прив'язкою до `CalculationRunId` і позначкою «за цим зрізом подано звітність».

**Фаза 2** ([B16](B16-ecr-reporting.md) §6) додає **переглядач**: рендеринг зрізу,
параметри, посторінкова навігація, document map, експорт XLSX/PDF, обране.
Це +8–10 тижнів FE і винесено за межі першої черги.

## 10. Workflow і обмін

* черга на затвердження, `Draft → Submitted → Approved`, коментар при відхиленні;
* порівняння версій документа, історія комірки (хто, коли, старе → нове, `IsLateEdit`);
* **імпорт `.xlsx` із попереднім переглядом diff** — що зміниться, до застосування;
* експорт: «з формулами» / «тільки значення», лист метаданих;
* i18n EN/RU/KZ: перемикач мови, локалізовані підписи з `…L10n`, формати чисел і дат.

| **FE-2** | `AccessProfile` приходить один раз на сесію; меню і доступність будуються з нього |
| **FE-3** | Ресурс рівня `None` не приходить з API — клієнт про нього не знає |
| **FE-4** | Довгі операції: 202 + `jobId`, прогрес `GET /api/v1/jobs/{id}`, скасування `DELETE /api/v1/jobs/{id}` |
| **FE-5** | Помилки: `errorCode` машиночитний, текст локалізований; `422` підсвічує конкретну комірку/поле |
| **FE-6** | Оптимістичні оновлення лише там, де сервер не може відхилити; інакше — очікування відповіді |
| **FE-7** | Автозбереження чернетки (ФВ-3.6) + відновлення після втрати з'єднання |
| **FE-8** | i18n EN/RU/KZ; нова мова — запис у `cfg.Language`, не збірка |
| **FE-9** | Доступність: клавіатурна навігація в усіх конфігураторах, не лише в grid |
| **FE-10** | Тести: Vitest + Testing Library на логіку, Playwright на 10 наскрізних сценаріїв |
| **FE-11** | Бюджет: перше корисне відображення < 2 с; відкриття таблиці 500×60 — у межах 1.5 с p95 разом із сервером |
| **FE-12** | Жодного бізнес-правила на клієнті: валідація дублюється для швидкості, але авторитетна — серверна |

## 15. Чек-лист

- [ ] Меню будується з `AccessProfile`, не з константи
- [ ] Ресурс `None` відсутній у відповідях API (перевірено тестом)
- [ ] Grid: вставка з Excel, fill, undo — на реальній таблиці 471×60
- [ ] Клієнтське значення формули ніколи не йде в збереження
- [ ] `null` / `isEmpty` / відсутнє поле розрізняються
- [ ] `lateEditReason` збирається у Grace-періоді, коли `requiresReason = true`
- [ ] `ChangeReason` обов'язковий у кожному діалозі публікації
- [ ] Публікація скрипта заблокована при червоному тесті
- [ ] Покриття правил показане до публікації
- [ ] Мапінг має перегляд на реальних рядках
- [ ] Типи API згенеровані, не написані руками
