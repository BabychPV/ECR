* Адміністратор створює роль «тільки читання по аркушу X» і призначає її —
  без жодного рядка коду
* Зв'язки між таблицями створюються у візуальному редакторі; цикл не дає зберегти

## Наступна фаза (за межами цього плану): розрахункові модулі емісій

Переносяться з PI AF у backend. Архітектура вже це передбачає:

* порт `ICalculationModule` у ядрі;
* схема `calc` у БД (методики, коефіцієнти, версійність методик);
* розрахунок як окремий тип `ColumnDef.DataType = Calculated` з посиланням на модуль;
* результати зберігаються як звичайні `CellValue` з `IsCalculated = 1`.

Детальний контекст буде додано окремо. **Що важливо зробити вже зараз:**
не «зашивати» припущення, що всі обчислювані значення — це формули Excel-типу.
`FormulaEngine` і `ICalculationModule` мають бути двома різними точками розширення.

## Можливий скорочений шлях (MVP за 6–7 місяців заявленою командою)

Якщо потрібен швидший результат — обмежити першу чергу:

**У MVP входить:**
* Конфігуратор (Етап 1) — обов'язково, це фундамент
* Введення даних + формули **для 3 аркушів** замість 18
  (рекомендую: `7. Water Report` + `7.0` + `8. Waste Report` — найскладніші, покривають усі патерни)
* Простий workflow: `Draft` -> `Approved` (без багатоетапності)
* Збір довідників і сирих даних з PI AF (адаптер, один транспорт — Web API)
* Експорт `.xlsx` (без імпорту)
