# Тестовий документ Land: усі методології з результатами

Один документ проєкту Land (`LANDUI2026`, шаблон 1.0.14.0 / TemplateVersionId 9), рядки якого дають кожній
покривній методології ≥ 1 `calc.CalculationResult`, 0 відхилених рядків і 0 помилок. Основа — таблиця покриття
`.sync-local/reports/LAND-ALL-METHODOLOGIES-coverage.md` (Tier A: 43 рядки в 28 таблицях, період **202609**).

| Файл | Що це |
|---|---|
| `land-test-doc.cells.csv` | дані: одна комірка на рядок — `row, table, methodology, rule, column, kind (lookup/text/number), value, source` |
| `land-test-doc.methodologies.csv` | план приймання: методологія → рядок, правило, очікувана кількість результатів, `knownConstantGap` |
| `Fill-LandTestDocument.ps1` | створення / доведення документа через публічний API |
| `Verify-LandTestDocument.ps1` + `verify-land-test-doc.sql` | перевірка після перерахунку (лише SELECT) |

## Стан даних: ключі з джерелом, числа — тестові

Ключові комірки (104: статус, тип обладнання/палива, IDCode, інвентарні номери, тексти потоків) мають джерело —
правило методології, комірку книги `Mapping_RDS_xxx_Template_Land_2025.xlsx` (аркуш!комірка) або запис довідника.
Числові входи (124) і вибір `ReleaseOnColdVentYesNo_M09` (A39) у книгах 2024/2025 і «Параметры_2024» відсутні
(порожні шаблони / річні параметри НДВ морського комплексу). Рішення 11.11 (варіант A, координатор): вони заповнені
**правдоподібними тестовими значеннями** з `source = test` — не з бекапів і не з реальних документів. Межі:
валідація шаблону (`docs/delivery/reference-data/land-template/land-template.model.json`, правила `DV_*`: години
вересня ≤ 720, дні ≤ 30/31, відсотки 0–100; сума по колонці таблиці теж у межах), гілки правил (A05 потужність 30 кВт
< 73.6 → `Loc_BeforeMR_A`; A21/A38 400 кВт), жодних нулів. A39 = `YES` (лукап `LAND_COLD2_VENTS_YES_NO`):
формула m42 `ECW_C12_03` має `if(ReleaseColdVent = 'No - Нет', 0, 1)`, за `NO` виходи були б нульові.
A14/A15/A18: `OperatingTimeReleaseOnColdVentYesNo_M09` (T9_04/T9_07) — `String` зі змішаним змістом «години АБО
`Yes - Да`/`No - Нет`» (D-423); окремої колонки годин немає. Yes/No читає лише C11_10 для NAE зі своїх груп; для
C11_02/C11_04/C11_05 це години (Legacy розбирає числовий рядок, LAND-POST-K3), тому там `600` (kind `text`).
⚠ m27 `ECW_C11_11_04` (Strict): входи `Benzene`/`Xylene`/`SaturatedHydrocarbonsC1C5`/`C6C10` (і `Toluene`) до шаблону
1.0.15.0 включно — String-колонки з числом; у Strict текст × число = `#VALUE` — ризик, видно лише після прогону. З 1.0.16.0
(AN-173) вони Decimal(34,16) у T9a_16/17/19/24–28, а мости `Land_MassFraction_0<код>` — числові 34/16.
Варіант B (реальні значення) змінить лише `value`/`source` у CSV — формат файла сталий.
Порожнє `value` або `source` → `Fill-LandTestDocument.ps1 -Execute` відмовляє (код 2) з переліком.

## Як запускати

Автентифікація — **наявна сесія оператора**: значення cookie `ecr.auth` після звичайного входу в браузері
(DevTools → Application → Cookies). Скрипт сам не входить, не створює облікових записів і ролей, cookie не друкує.

```powershell
$c = Read-Host 'ecr.auth' -AsSecureString
# план (лише читання): перевірка даних, сесії, пошук документа, які рядки/комірки змінилися б
.\Fill-LandTestDocument.ps1 -BaseUrl http://localhost:5094 -ProjectId 1 -AuthCookie $c
# запис + перерахунок 202609
.\Fill-LandTestDocument.ps1 -BaseUrl http://localhost:5094 -ProjectId 1 -AuthCookie $c -ConfirmStand localhost:5094 -Execute -Recalculate
# перевірка (Windows-автентифікація SQL, лише SELECT)
.\Verify-LandTestDocument.ps1 -Database EcrScratch_MB -PeriodKey 202609
```

Ідемпотентність: документ шукається за фіксованим ім'ям `LAND-TEST-ALL-METHODOLOGIES` (`-Marker`), рядки мають
ключі `LTD-A01`…`LTD-A43`. Повторний запуск дописує лише відсутні рядки й комірки зі зміненим значенням; на
доведеному документі нічого не пише. Зайві рядки `LTD-*` друкуються; видаляє їх лише `-Prune` (зайвий рядок дає
діагностику NoMatchingRule).

`-Recalculate`: якщо перерахунок усього документа дає HTTP 403 (вхід без права на документ цілком), скрипт рахує
по аркушах, де є таблиці CSV (`sheetDefId`, Q-331), по одному, не частіше 6 запусків на хвилину.

Вердикт `Verify-LandTestDocument.ps1`: для кожної методології — результатів ≥ 1, `CategoryRuleRejected` = 0,
`NoMatchingRule` на рядках `LTD-*` = 0, останній прогін не `Failed`, невдалих кроків (`CalculationStep.Value IS NULL`)
на її рядку = 0, крім KNOWN. Код 0 — прийнято, 1 — ні, 2 — немає документа / Current-прогону.
KNOWN — `knownConstantGap = yes` у `land-test-doc.methodologies.csv`; причину пише `knownReason` (типово «missing
constants»).

⚠ Невдалі кроки бачить лише прогін, що рахував рядок: на `ErrorsOnly` інші кроки не пишуться, а перенос результатів
(carry-over) кроків не копіює. Після поаркушного перерахунку Current-прогін рахував один аркуш, і рядок іншого аркуша
показує 0 невдалих кроків, хоч би що з ним було (11.11, док 96: A17/A37 — хибний OK). Тому при поаркушному перерахунку
`Verify-…` запускається після кожного аркуша, до наступного, з `-Tables T11_01,T11_02,…` (таблиці цього аркуша):
решта рядків — `NOT-CHECKED`, вердикт `PASSED (these tables only)`. Без `-Tables` — лише після перерахунку документа
цілком.

## Репетиція «Аудиту» і живий запуск

1. Репетиція — на scratch `EcrScratch_MB` з **новою версією Land, яку зібрали Permites** (опублікованою в цій
   scratch-базі): API на вільному порту над `EcrScratch_MB`, вхід своїм тестовим обліковим записом цього стенда.
   Спершу план (без `-Execute`): він покаже, чи всі колонки CSV є в новій версії (таблиці 6.x/7.x/9c змінюються —
   зниклу колонку скрипт називає й нічого не пише). Тоді `-Execute -Recalculate` і `Verify-…`.
2. Живий запуск — **лише після публікації нової версії Land на живому і лише у вікні** (маркер `WINDOW-ACTIVE`),
   тими самими командами; період 202609 має бути відкритим для запису (на 10.11 — Grace).
3. Після зміни версії шаблону — перезвірити таблицю покриття (колонки/правила), лише тоді CSV.
