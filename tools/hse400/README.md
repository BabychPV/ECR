# tools/hse400 — шаблон HSE400 «Компонентний склад газу»

Річний шаблон: один документ на рік, місяці — колонки `M01`…`M12`. Аркуш `GasComposition`, шість таблиць
(код таблиці = префікс AF): `FG_Makat`, `FG_HMB`, `LPG_HMB`, `FG_Export`, `FG_Internal`, `LPG_Internal`.

| Файл | Що це |
|---|---|
| `hse400-model.json` | модель: таблиці, рядки, підписи en/ru (згенеровано з вивантаження AF `Methodologies\HSE400\V1`) |
| `Hse400Model.Lib.ps1` | читання й перевірка моделі, місячні колонки |
| `Hse400Stand.Lib.ps1` | ціль, охорона стенда, виклики API |
| `Hse400Methodology.Lib.ps1` | чиста частина: модель → тіла запитів, план методології (аргументи, цілі `F_`, прив'язки) |
| `Build-Hse400Template.ps1` | шаблон + методологія + прив'язки + річний проєкт + документ |

## Що потрібно модулю місячних колонок (`MonthColumnArgumentsModule`)

`-Stage Template` будує саме це (тести — `tools/tests/Hse400-Methodology.Tests.ps1`):

- таблиці `MonthsInColumns`, колонки `M01`…`M12` з `isMonthColumn`/`monthNumber`, усі шість на аркуші `GasComposition`;
- у кожній таблиці прихована колонка-якір `HSE400_Calc` типу `Calculated`: прив'язка методології приймає лише
  обчислювану колонку (`ECR-TMPL-4227`), а місячні — ввід; модуль якір не читає;
- одиниця `one` у каталозі (немає — будівник зупиняється з поясненням);
- методологія `HSE400` (`Bespoke`), версія `methodology.version` — порожня чернетка рівня `Module` (клон рівня не
  змінює, тож версія з іншим рівнем — відмова), правило рядків `R_HSE400_ALL` = `{}`;
- формули/константи/тести — з `methodology.formulas|constants|tests` моделі (369 формул: 325 `HSE400_<таблиця>_<X>`,
  6 `Common_LHV0_*` і 38 спільних, на які вони посилаються через `!`; 223 константи); публікація лише коли формули
  є на всі 325 рядків `F_<X>` і є хоч один тест (без тесту сервер не публікує);
- **золоті тести**: модуль читає комірки документа, а не аргументи тесту, тож будівник створює окремий річний
  проєкт `HSE400_GOLD` з одним документом, пише туди синтетичний ввід тестів (місяць `M01`) і зберігає тест як
  адресу рядка `F_<X>` цього документа з очікуваним `{"M01": число}`. У робочий документ `HSE400_<рік>`
  синтетичний ввід не потрапляє; золотий документ не редагувати — на ньому тримається публікація методології;
- після публікації методології — активні прив'язки `{}` на якір кожної таблиці, вихід = формула першого `F_` рядка.

Не доведено до кінця (модель без формул або тесту) — попередження і код виходу 2; прив'язки до неопублікованої
методології не створюються (вони валили б увесь перерахунок документа).

Форма розділу методології в `hse400-model.json`:
`{"code","version","en","ru","effectiveFrom","formulas":[{"code","expression","arguments"?}],
"constants":[{"code","kind"?,"value","unit"?,…}],
"tests":[{"code","table","row":"F_<X>","month":"M01".."M12","inputs":{"<рядок вводу>":число,…},"expected":число,"tolerance":число}]}`.
Текст формул — дослівно з вивантаження AF (рушій приймає синтаксис AF: `@GCV.X`, `!Формула`, `CST.Константа`);
константа з кількома категоріями береться з категорії `Common`; одиниць константи не мають.

## Договір рядків (спільний із модулем місячних колонок)

- рядок **вводу**: `RowKey` = код компонента AF (`Methane`, `IC4_1`, …); аргумент методики — `GCV_HSE400_<таблиця>_<RowKey>`;
- **розрахунковий** рядок: `RowKey` = `F_<X>` для формули `HSE400_<таблиця>_<X>`, лише читання;
- модуль не читає рядки `F_` як ввід і не пише в рядки вводу.

Префікс `F_` потрібен, бо ім'я формули збігається з кодом вводу (`Nitrogen` у `FG_Makat`/`FG_Export`, вісім
кодів у `*_Internal`). Рядків вводу / розрахункових: 15/38, 34/58, 34/58, 16/41, 38/65, 38/65.

## Запуск

```powershell
powershell -File tools\hse400\Build-Hse400Template.ps1 -BaseUrl http://localhost:5094 -Database <база> `
    -ConfirmStand <база> -CredentialFile <шлях поза репозиторієм> -Year 2026 [-Stage Template|Project|All] [-PreviewOnly]
```

Лише локальна адреса; `-ConfirmStand` має дорівнювати `-Database`; файл облікових даних — один рядок
`користувач<TAB>пароль` поза git-worktree. Скрипт не створює облікових записів, ролей і баз. Повторний запуск
нічого не змінює: опублікована версія не чіпається, наявні проєкт і документ не дублюються. Стан — `out/` (не в git).

## Припущення й борг

- формули, константи й золоті тести внесено в модель разовим локальним генератором із вивантаження AF
  `Methodologies\HSE400\V1` (вивантаження й генератор не лежать у git). Імпорт `POST /methodologies/import` не
  підходить: він створює версії рівня `Configuration`;
- ⚠ золоті тести покривають два рядки `FG_Makat` (`F_H2S`, `F_EMercaptan`) — це сторож публікації, а не приймання;
  повна звірка чисел — на прийманні проти HSE400.Year. Прогін будівника на стенді ще попереду;
- шаблон, опублікований раніше з `PerPeriodInstance`, не правиться: будівник зупиняється — підніміть `template.version`;
- підписи рядків — як у старій системі, тож ввід і похідний рядок можуть мати однаковий текст (`Nitrogen` і `F_Nitrogen`);
- статичні довідкові колонки (молекулярна вага, теплота згоряння компонента) не перенесено;
- правил перевірки немає: правило задається на колонку, а в місячній колонці стоять рядки різної природи
  (% об., г/м3, температура); сума складу видна в рядку `F_TotalSum…`;
- відповідність рядків `Vog`/`Vo`/`VoH2O` рядкам звіту підтверджується числами на прийманні (HSE400.Year);
- звірка моделі з вивантаженням AF — разова локальна (вивантаження не лежить у git), у CI її немає. Результат
  11.11: із 500 рядків 496 мають ім'я `HSE400_<таблиця>_<X>` у вивантаженні; чотири рядки вводу
  (`Temperature` у `FG_HMB`/`LPG_HMB`, `TotalMercaptanSulphur` у `FG_Internal`/`LPG_Internal`) є в AF як атрибути
  вводу, але формули HSE400 на них не посилаються — їх лишено для вводу, як у старій формі.
